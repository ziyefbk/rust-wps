# 段落左右缩进与首行/悬挂缩进

后续有界扩展：显式已证明页面的顶层正文/标题可伸入页边距，见 [段落页边距外伸](PARAGRAPH_OVERHANG.md)。下述非负左右/容器内悬挂约束继续适用于缺省页面和单元格；旧轮次的证据与拒绝清单不被重写。

正文顶层段落、标题，以及受支持简单顶层表格的直接单元格段落可保存有限的左右缩进与首行/悬挂缩进。控件按当前段落或多段选区工作，保留默认/混合状态和显式零，支持撤销、草稿、DOCX 与不可变打印快照。列表编号的布局仍走既有明确规范化路径，不能把编号层级缩进冒充普通段落缩进。

## 模型与适配范围

可选整数 twip 属性：

- `indentLeftTwips`、`indentRightTwips`：旧容器路径 0–31680；显式页面的顶层正文范围见上述有界扩展
- `firstLineIndentTwips`：−31680–31680，正数为首行缩进，负数为悬挂，零显式清除首行偏移
- 三项仅限 `paragraph` / `heading`，省略保留默认；外部 JSON 的 null、字符串、浮点、布尔和越界值拒绝。编辑器内部 null 在快照中移除
- 控件使用 pt，0.05 pt 精度，不舍入；三项输入可为负数，是否允许由实际容器和页面校验。每项可独立恢复默认

数值上限不是适配证明。正文可用宽度来自显式页面，未设页面时采用既有 A4 DOCX 正文宽度 9026 twip。设左缩进 L、右缩进 R、首行偏移 F、容器正文宽度 W：后续行开始为 L、首行为 L+F，两者不能小于零，两个行框的剩余宽度必须严格大于零。这是段落行框约束，不证明任意长词、字体字形和所有自动换行都不会溢出。零/负行宽不自动裁剪或缩放；负左右与伸出正文的悬挂仅由上述显式页面扩展接受，其他容器继续拒绝。页面、列宽或表格结构编辑造成不适配时，整个候选事务在改动正文/历史/草稿前拒绝。

单元格按现有固定列宽或明确规范化的自动表格列宽，减去已设置的统一左右边距；省略时继续使用左右各 108 twip 的旧基线。后续边距模型与完整源证明见 [水平单元格边距](TABLE_CELL_MARGINS.md)。自动表格的宽度/余量算法与 DOCX 作者路径一致；仍不声称保留原自动列宽。只有带新段落缩进元数据的表格新增明确的左右 108 twip 声明和对应编辑/打印样式，旧无属性路径不改。嵌套表格、列表内段落及列表内表格不进入本次普通段落缩进子集。单元格缩进适配只证明该单元格的文字行框；未显式设置页面时，既有宽表格仍可能超出纸张，不因本次检查就成为整表适配证明。旧 V1 默认打印边距与 DOCX 默认页边距的历史差异同样未借本次重写。

## DOCX 源声明与继承

导出使用一个 `w:ind`：左右分别写 `w:left` / `w:right`，正首行或零写 `w:firstLine`，负首行写绝对值的 `w:hanging`。无任何新属性时不额外写缩进、单元格边距或包部件，V1/V2 历史模型继续按原编码。

`docDefaults`、实际默认段落样式、`basedOn` 链和直接格式按左右分量继承。首行和悬挂是同一个偏移槽；更近一级出现任一声明时替换该槽，显式零同样覆盖。只设置左缩进不能丢失继承的右缩进或首行。解析库补丁只修复这些既有表示的合并，不扩展编号层级、逻辑方向和字符单位支持。

同一个 `w:ind` 同时含 `firstLine` 和 `hanging` 时，标准和本轮 LibreOfficeDev 消费者的行为不同，因此明确拒绝，不任选一个值来声称保真。独立继承探针另保留这一差异证据。

转换前使用与解析器相同的有界源快照及实际 OPC 样式/编号/settings 关系检查声明。逻辑 start/end、字符单位、超出新物理页面子集的负左右值、RTL/镜像、模糊条件表格样式、未证明的单元格边距等不静默丢弃；仅活动样式链和实际使用的编号层级参与检查，未使用模板样式不应阻止普通文档。实际使用的编号身份必须明确，不能借助解析器的非法/缺省 ID→0 回退避开检查；未使用的畸形定义仍不因此阻止正文。涉及新缩进的未解析段落/表格样式及 basedOn 引用不猜测消费者默认样式回退；没有相关缩进声明的既有未知样式规范化路线保留。支持源段落的有效缩进还与转换后的值和文字顺序交叉核对，避免仅依赖解析器补出的默认值。

带新缩进元数据的段落不能含制表符；源中有效自定义制表位也拒绝，空制表位容器和普通手动换行不因此被误拒绝。正文分页/分栏符与缩进同段的布局不在本次范围内。图片段落不进入文字缩进保存承诺：既有单图审计确认形状、媒体和专用段落后，继续明确警告其普通缩进规范化，并只移除已核对的相邻空占位段落；不会跳过真实空段落、混合文字或多图。普通未缩进分页和既有单图路径继续独立验证。旧二进制 DOC 路径不因此扩大版式承诺。

## 独立证据与限制

定向源由 python-docx 与明确标记的 OOXML 边界变体生成，预期清单独立保存；源与输出由独立 OOXML 读取器和 python-docx 检查。另保留未经修改、固定 revision/hash 的上游真实文件，来源和许可范围见 `scripts/paragraph-indentation-corpus.json`；不将上游测试文件称为用户生产文档，不把自行改造的变体称为原件，也不分发未明确审查再分发许可的二进制。

LibreOfficeDev PDF 探针使用受控字体/字号和页面几何，比较首行、后续行横坐标及换行，包含源→输出与实际编辑→独立参考。它只证明该消费者的有限布局，不是简文浏览器 CSS、Windows WebView2、系统打印、Word 或 WPS 的验收。真实浏览器与原生 PDF 的既有环境限制未重试或绕过。HTML 粘贴只验证自有规范属性与受支持的物理 pt/px 样式；畸形自有属性或无法支持的活动物理缩进声明在事务前拒绝，不宣称任意逻辑方向/RTL CSS 粘贴保真。

最终执行命令、通过计数、未执行规格、源文件 SHA-256/禁止覆盖和完整模型反篡改结果见 [REGRESSION.md](REGRESSION.md)。

复现核心及独立文件检查：

```sh
cargo test --locked --test word_paragraph_indentation --test word_paragraph_indent_source
cargo test --locked
cargo test --manifest-path vendor/office_oxide/Cargo.toml --lib
npm run build
python scripts/check-word-paragraph-indentation.py --help
```

独立脚本的 `--render` 使用受控 LibreOffice，真实上游文件按清单固定版本下载后再传入；默认生成的定向文件均为合成样本。最终回归记录保留完整实际命令和输出目录，不能把浏览器规格的发现数量算成通过数量。
