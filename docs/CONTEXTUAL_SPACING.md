# 同样式上下文间距：有界的固定值转换

DOCX 的 `w:contextualSpacing` 可按相邻段落是否使用同一个段落样式改变段间距。简文现有模型没有动态命名段落样式；本次不增加一个失去原样式身份的布尔开关，而是在受支持的源文档中核对原始样式、继承和邻接关系，将可证明的初始间距转换为现有 `spaceBefore` / `spaceAfter` 固定整数 twip。审计及编辑导入均明确提示：源上下文间距已经实体化，命名样式与以后重排的动态行为不保留。

这让普通未改造 python-docx `List Number` / `List Bullet` 模板成为正向目标，不再为通过导入而删除其上下文声明。列表编号外观、起始值、层级缩进和制表位仍按原有边界处理；上下文间距支持不扩大这些能力。

## 先测量，再确定范围

[Microsoft Learn 引用的 ISO/IEC 29500 说明](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.contextualspacing?view=openxml-3.0.1) 规定先得到正常的相邻间距，再减去启用上下文的段落本身那一侧间距，最低为零。例子中前段段后 200 twip、后段段前 240 twip，只有前段启用，得到 40 twip。

本轮独立 LibreOfficeDev 消费者对该例子的行为不同：先取消启用段落本身的边距，再取剩余边距的最大值，得到 240 twip。反向启用和连续三个段落同样证明这个差异。另一个独立探针发现不同样式 ID 但重复显示名称时，LibreOffice 会按同样式消除间距；这种活动身份歧义也拒绝。不能用某一个消费者的行为冒充通用标准兼容，也不能简单地取消保护接受所有情况。

因此仅接受两种算法一致的边界：

- 两段原始段落样式身份不同：不取消间距，即使格式完全相同、继承同一个基础样式
- 同一段落样式、两侧均关闭：不取消间距
- 同一段落样式、两侧均启用：前段段后及后段段前都转为显式零，原值可不相等
- 同一段落样式、只有一侧启用：仅当原始前段段后或后段段前至少一个为零时支持；取消启用段落自己的相应边距
- 同一段落样式、仅一侧启用且两个相邻边距均为正：拒绝建立编辑副本，不私自选择 ISO 或 LibreOffice 结果

这里的零必须由受支持的继承或真实缺省解析得出，不能把自动间距、按行段间距或解析失败当成零。倍数行距仍由已有模型独立保留。

## 身份、继承与边界

使用与转换器相同的有界 DOCX 字节快照和实际 OPC 样式关系。源解析保存临时样式身份，按文档默认属性、所选默认或显式段落样式的 `basedOn` 链、直接格式分别解析 before/after/line 和 true/false；显式零及显式关闭覆盖继承值。省略 `pStyle` 与显式引用真实默认样式是同一身份；两个不同叶样式不是同一身份。活动样式的显示名或缺名时的 ID 发生歧义时拒绝；名称比较保守地忽略首尾空白和大小写。没有声明默认样式时，启用上下文的相邻段落若混合省略与显式样式引用，也拒绝：消费者可能按内置 Normal 回退合并身份。

先保留每个段落的原始有效值，再独立评估各相邻边界，最后一起应用固定值。前一边界修改 before 不能污染后一边界对 after 的判断。正文源顺序中的列表项和普通段落仍相邻，不由转换后列表包装器决定；整表和每个单元格边界中断邻接。首段段前及末段段后的外侧值不因没有邻居而被取消。

只有完整源段落/表格/单元格顺序、真实空段、文字、段落种类和列表归属能够与转换结果交叉核对时才应用。使用中的未知、重复、循环或模糊样式身份不猜测；不支持的活动编号级上下文和条件表格继承仍受保护。当前证明确实是整份文档的段落序列：只要有相关活动上下文声明，文档中任何图片、手动分页/分栏或不能一一核对的段落内容都会阻止该转换，即使那些段落自己没有启用上下文。不能把它描述成只限制启用上下文的图片段落。没有活动上下文特性的旧路径不额外转成命名样式模型。

## 编辑、导出与安全

没有新增模型属性、源样式 ID 或“上下文”开关。用户可继续用现有段前/段后控件修改固定值、恢复当前 profile 的默认值；一次操作一次撤销，纳入草稿和不可变打印快照。重排、分段及单段转为标题按普通固定格式处理，不声称像 Word 一样因新的样式邻居自动重算。当前已有多段选区转为标题的 Tiptap 路径会重置段落间距为缺省；本轮不将单段种类转换的保留结果外推到多段命令。恢复默认同样不恢复原 DOCX 的动态样式关系。

导出仍使用现有 `w:spacing`，不写未保留的 `contextualSpacing` 或伪造原命名样式。这是有明确提示的格式转换，不是原包无损重保存。可信自有模型仍经过完整部件集合、散列和重新编码验证；未知字段、外部 null、越界值等拒绝。未使用新转换的 V1/V2 模型保持历史编码，源文件不写入，另存禁止覆盖已有文件。

## 证据与未验证项目

定向文件由独立 python-docx/OOXML 作者路径生成，明确区分未改造模板、受控合成文档、独立固定值参考和未改造上游原件。用独立 python-docx/XML 读回、完整可信模型、源 SHA-256、不覆盖检查，以及 LibreOffice PDF 行基线验证受支持的初始间距和实际固定值编辑。PDF 页面必须一致，标记的绝对 y 坐标与相邻距离容差小于0.3pt；最终受支持组实测最大差0.0pt。源→输出与编辑→独立参考分开报告；标准/消费者不一致的拒绝校准不计为支持正例。表格边界的受控源明确指定与现有作者路径相同的 0.5 pt 边框；裸表格的既有边框规范化可造成 0.5–1 pt 纵向差，单列保留，不放宽测量阈值。真实空段保留并参与邻接。该轮 DejaVu 12 pt 空段与作者缺省字体曾测出 1.35 pt 差，因此当时的受控探针使用相同缺省字体隔离间距语义；后续有界真正空段字体修复独立保留并重测原反例，见 [EMPTY_PARAGRAPH_FONTS.md](EMPTY_PARAGRAPH_FONTS.md)。这不扩大动态样式或复杂空段保真承诺。
