# Rust 公式计算原型

桌面支持“计算公式”手动计算和可选的“自动重算”，CLI 也可输出独立报告；尚无增量重算或 XLSX 缓存写入：

```powershell
cargo run --locked -- calculate-workbook docs/examples/workbook-v1.json
```

输入为经过同一 Rust 工作簿模型校验的 JSON，输出独立计算报告；示例预算中的 `SUM(B2:B3)` 得到 1280。输入模型、原公式、工作簿文件及源缓存不被修改。外部工作簿默认只读，可经独立导入审计和用户接受变化后建立基础编辑副本。

固定的 `office_oxide 0.1.13` 提供公式读写和共享公式展开，没有本项目可直接接入的工作簿重算入口。原型在独立 `calculation` 模块中实现有界解析和按需依赖求值，不将第三方文档 IR 固化为计算模型。

## 已实现范围

| 能力 | 范围 |
| --- | --- |
| 常量 | 有限数值、科学计数法、双引号字符串、TRUE/FALSE |
| 运算 | `+ - * / ^`、一元正负号、后缀百分号、括号 |
| 引用 | 当前表 A1、`$` 固定坐标、单个跨表引用、单引号及转义名称、矩形范围 |
| 聚合 | SUM、AVERAGE、MIN、MAX、COUNT，最多 255 个参数 |
| 数学 | ABS、SQRT、INT、SIGN，均恰好一个标量参数 |
| 条件 | IF，2 或 3 个参数，未提供假分支时返回 FALSE；仅求值选中分支 |
| 比较 | `= <> < > <= >=`；支持数值间、布尔间比较，空白按数值 0 参与数值比较 |
| 依赖 | 按需递归读取、同次计算内记忆结果、循环检测、失败传播 |

固定/相对坐标在求值时均指向同一个单元格；复制公式时的平移由现有独立前端模块处理。范围可反向书写，会规范化为矩形。隐藏表参与计算。

运算优先级按一元正负号、百分号、乘方、乘除、加减处理，同级从左到右，包括 `-2^2 = 4`、`2^3^2 = 64`。依据：[Microsoft 运算符说明](https://support.microsoft.com/en-gb/excel/calculation-operators-and-precedence-in-excel)。数值采用 Rust f64，不承诺与 Excel 的全部浮点舍入、聚合和溢出细节一致。

聚合的单元格/范围参数忽略文字、布尔及空白；直接参数中的布尔和可解析数值文字参与计算。COUNT 忽略引用中的已知错误，但不掩盖“不支持”、循环或资源上限状态。普通算术目前支持数值、布尔及空白，文字自动转换尚未实现；这类公式报告不支持。单独引用空白单元格的公式结果为数值 0。聚合规则参考 [Microsoft SUM 说明](https://support.microsoft.com/en-us/excel/use-the-sum-function-to-sum-numbers-in-a-range)。

## 报告与失败

报告包含引擎标识 `bounded-numeric-v1`、`complete`、操作计数以及每个公式单元格的坐标、原公式、结果或失败原因。结果可为数值、文字或布尔。

| failure.kind | 含义 |
| --- | --- |
| error | 已知计算错误，例如除零 `#DIV/0!`、无效表引用 `#REF!`、非有限运算结果 `#NUM!` |
| unsupported | 引擎尚未覆盖的语法、函数或转换，不提供猜测结果 |
| cycle | 本次依赖遍历检测到循环，代码 CIRCULAR_REFERENCE；不是伪造的 Excel 错误值 |
| limit | 达到解析、求值或范围预算，代码 CALCULATION_LIMIT |

`complete=true` 仅表示本报告所有公式在该原型范围内得到结果或已知计算错误；不表示公式无错误，也不表示整个 Excel 格式兼容。unsupported、cycle、limit 均使 complete 为 false，独立可计算单元格仍可返回结果。没有用 0 或源缓存填补失败项。

IF 的条件支持数值、布尔及空白，支持嵌套并保留分支返回的文字/数值/布尔类型；未选分支不触发除零、引用求值或循环检测，但全部分支仍须通过解析，未知函数及无法解析的语法仍报告 unsupported。空参数、文字条件、文本比较、混合类型比较和地区转换尚未支持。语法依据：[Microsoft IF 说明](https://support.microsoft.com/en-us/excel/functions/if-function)；动态分支与循环处理尚无原生 Excel/WPS 对照验证。

拼接、命名范围、整行整列、三维范围、结构化引用、数组、动态数组、外部工作簿和地区公式语法仍未支持。外部链接不会读取磁盘或网络。未知函数与未支持语法返回 unsupported，而非假装已经重算。

## 资源边界

- 输入沿用工作簿上限：100 张表、100000 个实际单元格、4 MiB 文字/公式/格式；CLI JSON 最多 16 MiB。
- 单个公式最多 512 个词法项、256 个解析节点；解析嵌套最多 64 层。
- 表达式和单元格依赖合并计算求值深度，最多 64；避免分别重置深度导致递归栈累乘。
- 单个矩形范围最多 100000 个位置，包括空白位置；整次计算最多 1000000 个求值/读取操作。
- 达到上限明确失败，不生成部分范围和冒充完整结果。记忆结果和失败仅限本次调用，不跨编辑版本复用。

深依赖的预算结果可能随本次已记忆结果和单元格遍历顺序变化；应作为资源限制处理，不能当作稳定公式语义或存入 XLSX。

## 验证与后续

`tests/calculation.rs` 覆盖优先级、跨表/混合引用、范围类型、依赖、循环、错误、资源上限、空白公式值、CLI 及输入不变。`scripts/check-calculation.py` 通过真实 CLI 对照 200 组独立 Python Decimal 算术结果，生成 tmp 下报告；这不是 Excel/WPS 原生兼容对照，也没有把 openpyxl 当作计算器。

桌面 `calculate_workbook` 命令通过独立 `--calculation-worker` 执行，使用同一进程隔离机制：30 秒截止、Windows Job 提交内存 512 MiB、活动进程 1、响应最多 32 MiB。计算请求为最多 16 MiB 的工作簿 JSON，单独入口避免放宽打开/导入请求的 64 KiB 限制。`scripts/check-calculation-worker.mjs` 对照真实 worker 与 CLI，并检查两个入口的独立输入上限及非法模型。

前端在请求时捕获编辑器实例、修订号和修改代数；修改立即清空当前结果，迟到报告只有仍匹配原快照时才显示。完整校验报告引擎、坐标/公式集合、重复/缺失项、值类型和完成状态后一次发布。结果不进入草稿、撤销或编辑模型；计算期间可继续编辑，但离开/关闭需等待计算完成或超时。当前使用全量失效，不是增量依赖更新。

网格显示计算值或已知错误；不支持、循环和资源上限分别显示中文提示。格式显示可用于本次数值结果，公式栏与剪贴板仍保留原公式。另存 XLSX 保留公式且缓存缺失，不将部分或旧结果写入包。`tests/ui/workbook-calculation.spec.mjs` 覆盖真实 Rust 结果、报告验证、迟到丢弃、失败保留及实际导出缓存；原生工作簿冒烟脚本另覆盖真实 WebView2 按钮、IPC、隔离 worker、编辑失效和未缓存导出。

后续扩充函数/语法和原生 Excel/WPS 对照语料，再验证受支持类型的 XLSX 缓存及计算属性。更完整的依赖图和增量更新仍待实现，不能把现有按需递归称为完整增量计算引擎。

## 逻辑函数与错误回退

AND/OR 接受 1–255 个参数，数值和布尔参与逻辑判断，引用中的文字和空白被忽略；全部忽略时返回 #VALUE!。直接文字暂不支持。所有参数均求值，不会因真假已经确定而掩盖后续错误。NOT 接受一个数值、布尔或空白参数。

IFERROR 接受两个参数，仅在已知计算错误时求值备用分支，空白结果转为空字符串。不支持语法、循环及资源上限仍明确报告。规则参考 [Microsoft AND](https://support.microsoft.com/en-us/excel/functions/and-function)、[Microsoft IFERROR](https://support.microsoft.com/en-us/excel/functions/iferror-function)；原生 Excel/WPS 对照验证仍待完成。

## 自动重算调度

工具栏可开启“自动重算”，默认关闭。编辑模型首次开启或修改后等待 350 ms，再调用相同的隔离 Rust worker；连续修改合并为最新快照。一次最多一个请求，计算期间可继续编辑，旧结果按版本丢弃后自动计算最新版本。无公式时不提交请求；关闭选项或离开工作簿取消待执行计时器。已开始的请求仍按既有 30 秒截止处理，离开保护等待它结束。

工作簿暂停或保存期间推迟调度；失败不无限自动重试，下一次编辑或手动计算可重试。自动计算采用全量求值与全量失效，不是增量依赖图，不扩大函数覆盖，也不把结果写进模型、草稿或 XLSX 缓存。选项属于当前界面会话，未持久化为工作簿属性。

自动重算现已通过真实 WebView2 原生冒烟，覆盖连续修改后结果更新、关闭自动模式后失效、撤销与重新开启后的恢复、真实草稿/另存/关闭保护；openpyxl 独立检查数值、公式及无缓存，细节见 EXCEL.md。该原生用例未人工延迟计算进程；在途请求合并与并发上限由界面桥接实际 Rust CLI 的受控延迟用例单独验证。

## 基础标量数学

SQRT 返回非负平方根，负数为 #NUM!；INT 向负无穷取整，所以 INT(-8.9) 为 -9；SIGN 返回 -1、0 或 1，负零也为 0。支持数值表达式、单格依赖、布尔与空白的既有数值转换，范围与文字转换仍报告 unsupported。参数个数不符仍报告 unsupported，除零、循环和资源预算沿用现有传播规则，IFERROR 可捕获 SQRT 的已知数值错误。

语义参考微软 [SQRT](https://support.microsoft.com/zh-cn/excel/functions/sqrt-function)、[函数列表中 INT 定义](https://support.microsoft.com/en-us/excel/excel-functions-alphabetical) 和 [SIGN](https://support.microsoft.com/en-us/office/sign-function-0050bda1-6483-4601-bd38-a7e859314d52)。数值仍采用 f64，未承诺与 Office 的全部极端数值或类型转换一致。核心测试覆盖零/负零、正负数、嵌套与依赖、布尔/空白、非法参数、除零传播、循环及条件错误回退；界面使用真实 Rust CLI 验证自动更新与 #NUM! 展示。

验收结果：15 项 Rust 计算测试、9 项界面计算测试、严格核心 Clippy 和普通桌面构建通过。scripts/check-scalar-math-worker.mjs 验证真实桌面 --calculation-worker 与 CLI 报告逐字段相等，并核对负数取整、负零、#NUM!、IFERROR 和单格依赖，输入字节不变。新增函数尚未单独进行原生 Excel/WPS 结果对照。
