# 工具栏正文 / 标题转换

文字编辑器“正文 / 标题 1–3”下拉框现在逐段转换，修复跨段选区把每段格式重置为缺省的问题。原 Tiptap `setNode` 只在选区两端同属一个段落时复制属性；本应用不修改依赖，工具栏改用 `ui/word-block-type.ts` 中独立构造的候选事务。

## 保留范围

- 每个选中正文 / 标题分别保留对齐、段前、段后、倍数行距、左右缩进、首行 / 悬挂缩进，包括明确零、缺省值和不同段落的不同值
- 仅更改段落种类和标题级别，保留文字、硬换行、Unicode、字符样式与链接、光标待输入格式、文档默认样式和页面 / 表格几何
- 支持当前段落、正向 / 反向文本选区、整段节点选区、全选和表格单元格选区；选区恰好止于下一段文字起点时不修改下一段，实际选中的空段仍转换
- 一次操作是一个撤销步骤；后续正文 / 标题转换和输入分别撤销。重复选择当前类型没有新草稿 / 历史事务
- 固定值仍是固定值，不重新推断已导入的命名样式身份或上下文间距关系

未显式设置的字号、粗体及默认段距继续随正文 / 标题样式改变，这是类型切换的预期效果。保留显式格式不代表字体替代、自动分页或完整 Word / WPS 版式不变。

## 原子拒绝和边界

列表项首个块必须是正文段落。选区包含这类段落而请求标题时整次拒绝，其他可转换段落也不改变；不会解除列表、重排或偷偷只改一部分。列表后续段落可在父结构允许时转成标题，再转回正文；转换为正文保留列表容器。

图片和手动分页符不改动，只有原子对象的选区没有操作。若任何选中文字块或活动属性不能无损表达、父结构不允许、已知间距 / 缩进 / 页面约束不满足，或候选超出节点、深度、正文和草稿保存预算，整次候选被丢弃。候选与调用方事务隔离，失败不污染文档、选区、待输入格式或历史。这里的前端校验不替代 Rust 导出器的完整模型校验。

本轮修复的是应用工具栏入口。未经包装的 Tiptap `setHeading` / `setParagraph`（包括未改造的上游快捷键 / 输入规则）仍使用上游行为；测试保留明确标注的依赖特征对照，不能将它解释为工具栏的新行为。本轮没有承诺全部上游命令都已替换。

## 已复现的剩余用户入口

Windows 原上游快捷键仍注册在编辑器中，工具栏修复不拦截它们。`tests/ui/word-block-type-upstream.spec.mjs` 直接调用实际注册的回调 / 输入规则处理器，8 项用例证明以下现存风险：

1. 两段 `A` / `B` 分别设置间距 `[0,120,241]` / `[240,0,360]`，并设置不同对齐、左右 / 首行缩进；选区位置 1–5 后按 Ctrl+Alt+1、2 或 3，上游 `toggleHeading` 把七个显式字段都置为缺省
2. 对两段有不同格式的 H2 使用 Ctrl+Alt+0，或再次按 Ctrl+Alt+2 切回正文，七个字段同样丢失；撤销能恢复
3. 在已有显式段落格式的段首输入 `# `、`## ` 或 `### `，上游 Markdown 标题输入规则即使只处理一个段落也会重置这些字段，邻段不变

这些是当前依赖中的可达调用路径和无 DOM 处理器复现，未声称实际浏览器 / 原生按键已验收。下一增量应统一快捷键和输入规则的属性保留、历史与列表拒绝语义；在那之前应使用本次已修复的下拉工具栏完成保格式转换。

- `tests/ui/word-block-type-model.spec.mjs` 使用真实 ProseMirror 事务和历史，包含逐段属性、反向 / 边界 / 空段 / 单元格选择、列表失败、内容 / marks、保存预算和共享事务失败隔离
- `tests/ui/word-contextual-spacing-model.spec.mjs` 对固定上下文转换结果新增正向应用回归，同时保留上游原始命令的独立特征测试
- `scripts/convert-word-block-type.mjs input.json output.json 0|1|2|3` 是调用同一事务的无浏览器验证驱动，拒绝覆盖输出，并检查完整撤销 / 重做
- `scripts/check-word-block-type.py` 独立创作源 DOCX / 数值参考，经真实导入、上述事务、Rust 导出与可信重开，再用 python-docx / XML 和 LibreOffice PDF 核对；源文件散列及不覆盖另存单独验证
- `tests/ui/word-block-type.spec.mjs` 是真实工具栏 / 待送达 DOM 选区 / 列表失败的浏览器规格。本轮仅发现，未执行；无 DOM 事务不等于浏览器或原生 WebView 验收
