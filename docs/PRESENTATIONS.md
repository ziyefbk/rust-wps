# 演示文稿探索

当前新增 Rust `presentation::inspect_pptx[_bytes]` 与 CLI `inspect-pptx <file.pptx>`。它输出演示顺序、幻灯片 ID/隐藏状态、逐页文字、原始 EMU 尺寸、形状种类与边界框、嵌套组合结构，以及后端跳过的不可读部件。报告与未来编辑模型分开；不写入输入文件。

采用锁定的 office_oxide 0.1.13 PPTX 后端。解析前复用 ZIP 大小/CRC/重复项检查，再扫描全部 XML/rels，拒绝 DTD、截断和超过 64 层的 XML；总元素不超过 100 万。输入 64 MiB、展开 128 MiB、4096 ZIP 项；输出不超过 1000 页、10 万形状、4 MiB 逐页文字。后面三项为解析后输出限制，尚不能代替桌面 worker 的内存/时间约束。现已接入桌面 worker 与内容检查 UI，见下文。

边界框是源局部坐标，组合变换、旋转、母版/版式继承尚未解析到统一画布坐标。文字提取不证明视觉顺序或布局正确。图片、图表、主题、字体、动画、切换和交互均未渲染；不执行宏或访问链接。不可读部件保留在报告中，不能把缺失内容误报为空白幻灯片。尚未支持旧 PPT、编辑、保存或播放。

验证：`tests/presentation.rs` 检查顺序/尺寸/文字/组合/隐藏页、坏包、截断、深层 XML 和 DTD。`scripts/check-pptx.py` 用 python-pptx 1.0.2 自生成两页语料，以独立读取结果对照真实 Rust CLI 的尺寸、ID、形状边界与隐藏状态，并检查源字节不变。`tests/fixtures/basic-slides.pptx` 为自生成测试文件，无第三方演示内容；可用该脚本的 `--write-fixture` 重建。

桌面现已接入既有隔离 worker（30 秒、32 MiB 响应、Windows 512 MiB commit 配额）和原生文件选择器。使用同一有界源快照生成报告，前端提供幻灯片选择、隐藏页标记、逐页文字和嵌套形状清单；未提供编辑模型。文本通过 textContent 展示。打开失败保留当前页，切换文件或新建编辑文档会关闭演示检查视图。

界面回归使用真实 Rust CLI 报告，覆盖页序、组合形状、隐藏页、导入禁用、打开失败保留与视图清理。`scripts/check-pptx-worker.mjs` 对照真实桌面 worker 与 CLI，检查源文件不变。

已有近似位置画布：读取每个普通文本形状的文字（段落/显式换行和字段缓存），EMU 换算为 96 DPI 逻辑坐标，SVG 按源宽高比缩放；采用默认 18 pt 字号、形状边框和每框独立裁剪。只绘制顶层形状，组合、图片和图形框使用占位标签。它不恢复原始字体/字号、自动换行、边距、旋转、组合变换、母版或主题。尺寸缺失/异常或读取失败时不给出画布，文字检查仍保留。画布最多 500 个顶层形状，每框最多 100 行；无效边界及数量截断会提示，完整文字仍在正文检查中。

界面验证包括真实源坐标、可见文字高度、裁剪、翻页更新、尺寸缺失、非法边界、形状上限及不执行输入 HTML。截图检查发现浏览器限制过大 SVG 字号，改为逻辑坐标后文字可见并补充高度断言。独立 python-pptx 对照扩展到逐形状和组合子形状文字。

下一步：完善段落布局、组合变换与图片，再实现可验证的新建/编辑/另存 PPTX。真实 PowerPoint/WPS 视觉对照尚待完成。

直接文本样式已贯通：形状报告新增可缺省的 `runs`，保留文字、直接字号（百分之一 pt）、粗体/斜体三态及直接 RGB 色。段落和显式换行转换为换行项；字段仍使用缓存文字。画布按行最大字号估算行高，同一行保留不同 run 的样式，缺省使用 18 pt 常规字和默认色。字号转换为 96 DPI 逻辑像素，不能把原始 pt/EMU 大数直接当成浏览器字号。暂不恢复字体族、下划线、段落对齐/缩进、列表、自动换行与主题继承。

每个形状至多 10000 个文字项；4 MiB 输出文字预算同时计入逐页正文、逐形状正文及 runs 中的重复文字。python-pptx 对照增加直接字号/粗体/斜体/RGB，Rust 和 UI 测试核对同一自生成 24 pt 彩色粗斜体语料；截图检查确认可见效果。

内嵌图片预览现支持 PNG/JPEG：按字节签名识别、读取尺寸并在内存预算内完整解码验证，随后将原字节作为受限 data URL 传到画布。单图 4 MiB、边长 10000、1600 万像素、解码分配 80 MiB，整套演示预览图原字节合计 8 MiB（重复引用按次计入）。缺失/坏图、超限和其他格式保留原因及占位；不获取外链，不加载 SVG/EMF 或执行活动内容。UI 仅接受严格 PNG/JPEG base64 URL，并在解码失败时提示。

图片按源边界拉伸，尚未恢复裁剪、效果、透明度、翻转、旋转或母版图片；组合内图片仅保留报告，不绘制。独立 python-pptx 对照核对图片字节，Rust 测试验证 PNG/JPEG、截断、非法格式与预算保留；UI 验证图片坐标、真实解码尺寸及拒绝外链/SVG。

## 文字替换与另存原型

Rust `presentation_edit::replace_pptx` / CLI `replace-pptx <input.pptx> <new-output.pptx> <find> <replacement>` 已实现原件只读的文字修改。当前范围明确限于标准 `ppt/slides/*.xml` 中单个 DrawingML `t` 节点，识别命名空间而非固定前缀，解码 XML 实体后执行字面全量替换。不会跨 run/段落/字段，字段缓存、备注、母版、版式和其他部件不参与。输出文字重新转义；周围 slide XML 与未修改 ZIP 部件 payload 保持原字节。ZIP 压缩和元数据会重新生成。

拒绝签名包、宏包、不可读部件、空/同值/超长查找或替换、替换中的控制字符和首尾空白。查找与替换各不超过 64 KiB，增长预算 8 MiB；最终输出继续受读取/报告上限约束。无匹配不创建文件；目标必须不存在。先重新读取实际输出包并核对全部部件、页数和解析完整性，再通过同目录临时文件、fsync 与不覆盖发布写入目标。

测试核对原件哈希/字节、其他部件逐字节保留、XML 实体、命名空间别名、字段排除、跨节点不匹配、增长上限、签名/宏拒绝及既有目标保留。独立 python-pptx 重读修改后的文字、字号、粗斜体和图片字节通过。现已接入桌面替换操作，但不是任意文本框编辑或演示新建模型；跨 run 替换与布局变化仍待实现/评估。

桌面提供查找/替换并另存 PPTX，原生对话框选择新目标后通过隔离 worker 写入。取消或失败保留当前页及输入；成功后读取实际保存副本，更新预览与后端当前路径，并保留所选页，后续操作基于副本。IPC 请求仍受 64 KiB 总大小约束。界面回归覆盖取消/失败/成功与实际 CLI 导出重读；真实 worker 验证另存、重开、原件不变及拒绝覆盖。原生文件对话框本身尚未做自动交互验收。

退出保护已验证覆盖 PPTX 替换：共享文件操作的 paused 状态会拒绝操作未完成时的关闭请求，提示稍后重试，替换按钮与选页控件保持禁用；成功、取消或失败结束后可再次请求关闭。新增三个保持 IPC 未完成的测试验证这些路径，并与 Word 生命周期回归共同运行（13 项通过）。这些测试模拟 Tauri 关闭事件/销毁 IPC，不等同于原生 WebView 或文件对话框交互验收。当前策略是阻止本次退出并允许用户重试，不会在保存结束后自动关闭。

## 新建演示模型 v1

`presentation_model::Presentation` 与 CLI `create-pptx <model.json> <new-output.pptx>` 提供独立于外部读取报告的新建文本框模型。示例在 `docs/examples/presentation-v1.json`。字段包括固定 version=1、EMU 页尺寸、按序幻灯片和文本框；文本框包含边界、Unicode 文字、直接字号、粗体、斜体和 RGB 色。换行写为 DrawingML 显式换行，空白页保留。模型及所有子对象拒绝未知字段。

限制：1–100 页、共 10000 个文本框、总文字 1 MiB、每框 1000 行，页尺寸每边 1–100 英寸、文本框必须完全位于页内、字号 1–400 pt；拒绝非换行控制字符。CLI JSON 至多 4 MiB，生成包至多 64 MiB。只支持文本框和空白页，尚无图片/图表/组合/主题/动画或隐藏页编辑属性。

使用锁定 PPTX writer，输出后由实际读取入口重开并逐页核对形状数、文字、坐标和直接样式，再通过临时文件、fsync 和不覆盖发布导出。Rust 测试覆盖多行中文及尾部空行、空白页、错误模型、未知字段和已有目标保留；`scripts/check-pptx-authoring.py` 用独立 python-pptx 核对尺寸、页序、文字、坐标、字号/粗斜体/颜色及拒绝覆盖。模型现已随 PPTX 保存并可验证重开，见下文；不授予外部文稿编辑能力，桌面新建/编辑已接入，草稿及撤销历史已接入。

## 自建 PPTX 验证重开

导出会写入 `/rust-wps/presentation-v1.json` 并登记 application/json ContentType。`load_authored_pptx[_bytes]` / CLI `read-pptx-model <file.pptx>` 只在模型校验通过、重新生成的全部 ZIP 部件 payload 与实际文件完全一致时返回编辑模型。比较包括模型本身、幻灯片、关系、内容类型、主题和所有其他部件，不能仅靠嵌入 JSON 声明授予编辑。ZIP 压缩/时间戳不参与 payload 比较。输入 64 MiB、嵌入 JSON 4 MiB，继续使用 ZIP 展开、CRC 和重复项限制。

外部无模型文件返回 None；幻灯片变化、模型变化、额外部件、旧版本 writer 生成差异均会拒绝编辑重开，可另走只读检查。严格比较可能把经过其他软件规范化的自建文件降为只读，当前不做猜测导入。文字节点替换功能保留其他部件，因此替换自建文件后其旧模型会失配，不能再据该模型编辑；模型编辑应重新导出完整一致的自建包。

测试覆盖导出→模型重开→修改→另存→再次重开、三个篡改/未建模场景，以及外部文件无模型。独立 python-pptx 重读仍通过，CLI 同时核对恢复的模型 JSON 与输入相等。桌面现已消费经验证的自建模型，见下文。

## 演示草稿恢复

独立草稿槽 `presentation-draft-v1.json` 与 Word/Excel 分开，Rust save/load_draft 先验证模型与 4 MiB JSON 上限，通过同目录临时文件、fsync 和替换提交更新；无效修改不会覆盖旧草稿，损坏/未知版本/超限输入报错。桌面提供 save_presentation_draft/load_presentation_draft 与“恢复演示草稿”。

编辑变化后延迟 700ms 自动保存快照，单队列串行写入；每次快照记录 owner/revision，旧结果不会把新修改标记为已保存。页和文本框增删、文字、样式和位置均进入同一草稿。新建和恢复默认未另存，恢复后仍需另存 PPTX。成功导出不会删除草稿。

离开前暂停输入，取消未开始计时，串行等待前次写入后保存最新快照；失败阻止离开并保留文稿，用户可重试。文件操作期间不会进入离开流程。界面测试验证首个草稿写入被阻塞期间继续编辑，关闭前保存最新文本/样式，再恢复；磁盘失败阻止切换及恢复后的关闭重试。Rust 测试验证更新、重读、无效模型保留旧草稿及坏 JSON 拒绝。原生窗口/文件对话框交互仍未自动验收。

## 演示撤销与重做

文本、字体样式、颜色、位置、文本框和幻灯片增删使用共享历史；提供按钮与编辑面板内 Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z、Ctrl/Cmd+Y。回退时恢复所选页和文本框，撤销删除页可找回整页内容。新修改清除重做分支，相同内容不增加历史。

历史同时限制为 100 个快照、32 MiB UTF-8 JSON，总预算包含撤销与重做；超限丢弃最早历史。历史仅存在于本次编辑会话，草稿恢复和重新打开建立新历史。每次撤销/重做增加草稿修订号并触发自动保存；内容与最近成功另存快照相同即清除未另存标记，失败或取消另存不会改变该基准。原生文件操作和关闭保存期间禁止回退。

验收：历史预算与分支测试、删除页恢复、文本样式/坐标回退、快捷键焦点连续输入、草稿与真实 Rust PPTX 导出重开均通过；全量界面回归 95 项通过，TypeScript 检查及桌面 debug 构建成功。界面 IPC 由测试桥接，PPTX 生成/重读执行真实 Rust CLI，尚未自动验证原生 WebView 快捷键。

## 窗口放映与系统全屏

只读 PPTX 和自建编辑器提供“从当前页放映”。模态窗口按画布比例适配视口；跳过隐藏页，显示放映页序与源文件页码。若当前选中隐藏页，从第一张可见页开始；全部隐藏或无页时禁用入口。左右/上下方向键、PageUp/PageDown、空格和 Enter 翻页，Home/End 跳首尾，点击画面前进，Esc 或退出按钮结束；首尾停留，不循环。聚焦按钮时空格/Enter 保留原生按钮行为。

放映从最新编辑模型生成快照，复用有限文字样式与 PNG/JPEG 画布，不显示普通文字框/图片辅助边框。每次画布有独立 SVG 裁剪 ID，避免与编辑预览互相引用。读取失败或尺寸未知时展示安全文本回退及说明；组合、旋转、主题、母版、动画等原预览限制继续适用。

预览按已换行的近似文本块高度计算剩余空间，包含各行字形下沿；空间不足时不向负方向挤压，沿用溢出提示与 PDF 阻断。此算法不恢复 Office 原字体、行距、段落间距或自动缩字，仍须复查复杂文字。第三方解析器本身不暴露 bodyPr 的垂直对齐；后续已从有界 XML 补充显式属性读取，详见下文。继承样式仍不恢复，导入审计明确提示。

验收：9 项演示模型和 8 项导入测试、严格核心 Clippy、22 项相关界面回归通过。新增模型测试覆盖三种属性、草稿、完整模型重开、原有 wrap/inset 保留和非法枚举；界面检查顶部/居中/底部基线位置、历史和草稿、PDF 快照一致性与溢出阻断，并用真实 Rust 导出及 python-pptx 独立核对底部属性。尚未新增原生 WebView2 垂直对齐导出验收。

## 外部显式垂直对齐

已绕过第三方 IR 缺少属性的限制，从有界 OOXML 快照读取显式 bodyPr anchor。按 presentation.xml.rels 的关系 ID 解析实际幻灯片路径，再按标准 PresentationML 对象 ID 关联到报告；接受任意正确命名空间前缀，检查 sp/nvSpPr/cNvPr 与 sp/txBody/bodyPr 的直接路径。重复关系 ID（含不同关系类型）、重复对象 ID 或重复 bodyPr 不挑选任意属性；未知值使用固定 unsupported 标记，属性长度上限 4096。关系目标仅包内规范路径，外部/异常目标不参与关联。沿用全包 XML 深度与节点预检。

报告可给出 t/ctr/b/just/dist；近似预览和 PDF 支持 t/ctr/b，基础导入保留这三种显式属性，缺省、继承和其他形式仍顶部规范化并提示。布局与母版垂直继承尚未恢复。自建导出现在重读并直接核对属性，仍保留完整整包模型验证。

新增两个纯解析测试覆盖实体、命名空间与路径伪装、重复 ID/属性、关系顺序及路径；26 项演示读取/模型/导入测试通过，模型测试新增三种属性的读取与重新导入。18 项界面回归与严格核心 Clippy 通过；python-pptx 外部样本经真实 CLI 读取，验证只读画布和 PDF 快照底部定位。此证据不等于复杂模板视觉保真或原生 WebView2 导出验收。
