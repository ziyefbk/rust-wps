# 单图段落间距、对齐与有限基线字体

正文顶层、单独行内 PNG/JPEG 的段前、段后、倍数行距和水平对齐现在可保留、编辑并另存 DOCX。选中图片后使用“图片段落格式”内的数值与对齐控件，点击“应用图片段落”；“默认图片段落”移除本组设置。尺寸、原始媒体字节和本组段落设置分别维护，两个重置互不隐式清除另一组属性。

这不是任意行内混排或完整 Word/WPS 页面复制。混合文字、多图同段、表格/列表图片、浮动、裁剪、旋转等原有拒绝边界不变。源页面尺寸、边距、段落缩进、分页控制及其他复杂布局仍可能规范化。基线字体是有界的普通从左到右 Latin 字体度量；缺字替代、字体未安装、复杂文字和不同排版引擎仍有差异。

## 模型与旧字节契约

图片新增可选 `attrs.imageParagraph`：

- 必须同时提供 `spaceBefore` / `spaceAfter`（整数 twip，0–31680）、`lineSpacing`（整数 1/240 行，120–2400）、`textAlign`（`left` / `center` / `right` / `justify`）
- 可选的 `paragraphFont` / `runFont` 必须同时存在；每个对象恰含 `family`、`halfPoints`、`bold`、`italic`。字号为 2–3276 整数半点，字体名遵守已有 31 UTF-16 单元字面字体规则，两个标志必须为布尔值
- `paragraphFont` 表示有效文档默认和段落样式的文字字体，用于段落行框；`runFont` 表示字符样式/直接格式后的图片 run 字体。它们不等于 `w:pPr/w:rPr` 段落标记格式。无法同时证明可移植字体时，两个字体对象一起省略，并明确警告基线可能改变；间距和对齐仍保留
- 外部 JSON 的显式 `null`、部分字段、未知字段、字符串数值、非整数、越界及非正文顶层图片位置均拒绝。编辑器内部的 schema 默认 null 在保存快照中移除
- 只有段落元数据而没有显式宽高时，浏览器仍沿用旧响应式自然尺寸，Rust 仍沿用旧 600×800 px 上限算法；不能因此宣称实际浏览器物理尺寸已一致。新显式尺寸分支才使用相同 EMU 显示框
- 不要求同时设置显示宽高；一旦存在任一宽高，仍必须为完整合法 EMU 对。仅段落元数据也触发严格图片媒体校验、100 张、单张 8 MiB、合计 20 MiB 和整个草稿预算

省略 `imageParagraph` 时保留历史 V1/V2 编码分支；既有无尺寸和仅尺寸模型的部件字节不自动升级。重置段落设置恢复原分支，可能改变位置和后续正文间距；这不是恢复导入时的源格式。V2 图片首次主动应用段落设置取编辑默认 0/120/360；旧 V1 取原编辑视图的 0/180/456，只有主动应用后才把它们实体化。旧 V1 编辑与打印默认之间的历史差异没有趁机改写。

## 同一快照的有效样式解析

图片关系、MIME、字节哈希和两组 extent 仍由原尺寸审计证明。新的段落解析读取同一有界包与实际 styles/theme 关系，按 docDefaults、活动段落样式 basedOn 链、直接 pPr 分量合并间距/对齐；字符样式与直接 rPr 分别解析图片 run 的字体。活动链的重复、循环、命名空间歧义和不支持声明不能静默掉回默认。未使用的模板样式不构成已使用格式。

EastAsia/CS 字体槽和语言元数据不进入这个 Latin 基线模型，仍可能规范化；不根据 settings/themeFontLang 猜测多脚本行框，也不宣称多脚本字体度量完整保真。

字体只在有效 ascii/hAnsi 字体槽一致且字号明确时实体化；支持通过实际主题关系解析有限 major/minor Latin 字体，转换后为固定字面名称。样式的粗体/斜体按 OOXML toggle 语义计算，直接 false 可关闭。启用的复杂文字/RTL、非默认字体 hint、非零基线位移/字符间距等拒绝；段落标记字体若与段落样式字体不同，同样拒绝，避免用一个字段冒充两套度量。

支持的倍数行距保持 `lineRule=auto`；固定/最小行高、自动/按行段间距、活动 contextualSpacing、活动文档网格等仍拒绝。未规定 type 或 type=default 的 docGrid 不被当作活动网格。图片所在源段落被解析器提升为相邻图片节点时，仅移除其紧前方经审计的空占位段；额外核对该占位段的有效间距和对齐，真正相邻空段落不合并。

## 导出与编辑/打印语义

新分支在图片段落写出明确的 `w:spacing` / `w:jc`。可证明基线字体时，为每张图片生成确定且无冲突的专用段落样式，承载 `paragraphFont`；图片 run 单独写 `runFont`。不改全局 Normal 或旧 profile 默认值。新增样式和 settings 部件纳入已有完整集合、哈希及重新编码保护；外部修改并同步伪造哈希也不能直接可信重开。

编辑器使用真正的块级段落外框、单独的 run span 和 baseline 行内图片；外框负责间距、对齐和段落字体。打印克隆使用同一声明。数值应用、重置各为一次撤销；草稿保留完整元数据。控制器绑定当前文档、图片节点和选区，保存锁、切换选区、迟到事件及超预算修改不能修改另一张图片。

这些 DOM/事务测试不等于真实 CSS 布局。现有 Chromium、云预览连接、Linux 桌面依赖和 Windows 环境限制仍未解除，本轮没有重复尝试或绕过它们，也未声称简文原生 PDF 或 Word/WPS 视觉验收通过。

## 根因与独立消费者证据

前一轮受控 50 pt 高图片后多出约 12.3 pt。39 个只修改目标声明的 LibreOffice 诊断变体分离出原因：默认段后 6 pt 加 1.5 倍行距的额外 6.3 pt；恢复源 0/0/240 后，后续文字基线与源完全相同。不存在用固定负间距补偿或插入空格的修正。

7.5 pt 小图片揭示另一问题：仅恢复间距仍差 1.35 pt；在图片 run 或段落标记直接设置源字体均无效，而专用段落样式同时设置源字体名与字号后恢复源基线。字体名或字号单独修改均不够。因此测试同时保留大图、小图及不同源字体，不能从单张大图结果泛化所有行框。

诊断证据：`tmp/image-paragraph-gap-probe/summary.json`。它记录 39 个变体、源哈希和三个分组报告；仅证明 LibreOffice 的受控行为。

```sh
cargo test --locked --test word_image_paragraphs
python scripts/check-word-image-paragraphs.py --cli target/debug/rust-wps --render --corpus-dir tmp/image-corpus
```

独立套件使用 python-docx 定向源、独立 XML 样式读取、完整可信模型、媒体字节和 PDF 图片坐标/后续基线对照；未改造的固定上游图片正对照与自制样本分列。最终计数、最终 CLI 哈希、回归结果与尚未执行的浏览器验收见 [回归记录](REGRESSION.md)。源文件始终保持哈希不变，输出必须另存且拒绝覆盖。
