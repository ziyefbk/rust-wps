# 简单表格的最小行高与单元格垂直对齐

正文顶层、无合并、无嵌套的矩形表格支持逐行最小高度与逐格顶部 / 居中 / 底部对齐。光标修改当前行 / 单元格；跨单元格文字选区、单元格选区与整表节点选区按实际覆盖范围修改。控件显示默认、显式值和混合状态，行高与垂直对齐可分别重置；候选整次校验后提交，一次撤销，保存锁定与过期选区不会误改其他表格。

## 模型、导出与编辑

- `tableRow.attrs.rowMinHeightTwips` 是可选非负整数 twip，绝对上限 31680，另不得超过当前页面正文高度。缺省 A4 的上限为 13958 twip；显式页面按纸张高度减上下正文边距计算。界面输入 pt，精度 0.05 pt
- `tableCell` / `tableHeader` 的可选 `cellVerticalAlign` 只接受 `top`、`center`、`bottom`
- 省略与显式 `0` / `top` 不同；默认操作删除对应属性。原始 JSON 的 null、字符串数字、布尔、浮点、负值、越界和错位属性拒绝，Tiptap 内部 null 缺省在保存快照中移除
- DOCX 写出 `trPr/trHeight` 与 `hRule="atLeast"`，以及 `tcPr/vAlign`。不写精确高度，不限制内容到一个固定剪裁框。文字超过最小高度时可以自然增高；不承诺任意长内容的跨页版式
- 草稿、完整模型可信重开与不可变打印副本保留值。没有新属性时保留旧 V1/V2 编码字节，不升级 profile 或改全局兼容模式
- 新增行 / 列使用默认的新行 / 单元格属性，保留其余行格的身份与格式；删除行 / 列同样只移除对应内容。已有表头类型切换保留数值，自有表头沿用既有 DOCX 重复表头声明；其实际跨页表现未验收
- 缩小页面或增加上下页面边距导致已有最小行高超限时，整次候选拒绝。此上限是作者模型约束，不是自动分页、行框高度或字体适配的完整证明

编辑器与打印副本保留相同的内联 `height: …pt` 表格行声明和 `vertical-align` 单元格声明。CSS 原生表格行的 height 是最小约束，不使用不可靠的 tr min-height、max-height 或 overflow 剪裁。编辑器历史上下单元格内边距仍是 8px，受支持 DOCX 源 / 输出的上下边距为 0；未通过实际浏览器 / 原生打印验证，不能据此声称两者物理基线相同。

## 外部源的有界证明

原始 DOCX 在同一个有界字节快照中读取、审计和转换。新的审计补充了 vendor 对未知枚举静默缺省及缺少这两类表格样式继承的问题：

1. 仅直接正文表格的直接行 `trPr/trHeight`、直接单元格 `tcPr/vAlign` 可进入子集。高度规则只能省略或为 `atLeast`；`exact`、`auto`、未知值、缺值、重复、包装、错误命名空间 / 前缀及属性碰撞拒绝
2. 显式表格样式或实际使用的隐式默认样式，以及完整 basedOn 链，均须可唯一证明。活动继承或条件行高 / 垂直对齐即使被直接值覆盖也拒绝；未知、重复、循环、包装继承边和模糊默认身份不猜测。未使用模板声明不会单独触发新拒绝。索引、链和默认引用缓存，链深度与累计工作量另有上限
3. 新保留路径的上下单元格边距必须省略或每个实际声明都是完整物理 dxa 零值；检查直接表格、逐格和活动基本 / 条件样式。非零、未知边、冲突、包装、缺单位 / 缺数值等拒绝，不能用直接零覆盖来掩盖未支持的基样式语义。完全省略的一边沿用 OOXML 默认零。没有新垂直属性的旧导入仍走既有明确规范化路径
4. 新路径仍拒绝合并、参差、嵌套、行 / 格修订、隐藏、重复表头、cantSplit 和复杂文字方向声明，包括尚未证明的中性 / 关闭变体。单元格限定直接普通 / 标题段落；编号段落和复杂内容不会由本增量默认为受支持
5. 审计结果与 IR 的表格 / 行 / 格数量和顺序、原始高度规则 / 数值、对齐、有无分页限制以及每格完整段落文字 / 空段身份核对，再附加到模型。禁止把缺省转换值当成原始证据

页面审计仍保护节级 vAlign。这里只为严格直接的单元格路径留出由表格审计接管的出口；没有全局忽略 vAlign，也没有放开其他节属性。

自有表头模型可编辑 / 可信重开与外部复杂表头导入是不同范围：去掉可信模型后把带本轮属性的重复表头当外部源导入，仍可能按上述保护拒绝。原件、已有输出和失败草稿保持不变，继续只创建新的 DOCX 副本。

## 未改造真实文件与独立消费者

正对照是 Apache POI `TestTableCellAlign.docx`，固定 revision `ae62bb5116b9aee19ebd5834e3a82066132c9f7f`，[原始来源](https://github.com/apache/poi/blob/ae62bb5116b9aee19ebd5834e3a82066132c9f7f/test-data/document/TestTableCellAlign.docx)。11712 bytes，SHA-256 `2968d4a5d5de21dce1cbeae3235e545cdf4bfd7ae508fe0eed3a9b032773ce17`，Git blob `cf40dd2213a44972cce7f1bccdfd6f9db8933386`。这是未改造的公共上游回归样本，不是用户生产文档；原始二进制不提交、不另存改造后冒充原件。

原件 2×2 表格直接最小行高 1340 / 1160 twip，hRule 省略；Top 格对齐省略、Bottom 格为 bottom、Center 格为 center，第四格为空。活动 TableGrid → TableNormal 不含继承或条件行高 / 对齐。LibreOffice 独立读取原件为一页 Letter：边框中心线 y=72.25 / 139.75 / 198.25 pt，行距 67.5 / 58.5 pt；Top / Bottom / Center 文字基线分别 83.20 / 136.75 / 172.95 pt。Calibri 在该消费者替代为 Carlito 11。

原始自动网格总宽 9350 twip 仍按既有导入 / 页面规则规范化；边框 x 位移单独登记，不将纵向比较当成整页或横向相等。边框外观及未建模格式也保留既有规范化提示，不把这个子集扩大为任意表格外观保持。

`scripts/check-table-vertical-layout.py` 使用 python-docx + 原始 XML 独立读取，分别验证原件、独立作者样本、实际修改后的应用输出和另行创作的修改参考。LibreOffice / PyMuPDF 量取边框、相对文字基线、长文字自然增高及全部文字；完整可信模型、不覆盖、无属性整包金样、原件散列和包括修复哈希在内的篡改拒绝另检。最新冻结身份、通过计数与报告见 [REGRESSION.md](REGRESSION.md)。

历史源 `table-alignment.docx` 的补充核对确认6表18行原始最小高度都是341twip。新输出的每行边框间距与源相同，修复旧输出每行少0.7pt的差；但表间真正空段仍因既有基线字体 / 行框规范化少4.3pt，后续表格起点继续累计漂移。此残留已单列，不能用正确行高推断完整页面纵向相等。

独立 LibreOffice 渲染不是本应用浏览器 / WebView / 原生打印，也不是 Word/WPS 的完整验收。实际浏览器、输入法、系统剪贴板及原生打印仍待可用环境验证；不重试已经确认的受限路径。
