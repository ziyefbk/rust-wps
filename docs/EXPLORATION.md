## 起步选择（历史实验记录）

- 桌面：已接入 Tauri + TypeScript/Vite，当前为正文阅读、文本替换和 PDF 阅读工作区。自由富文本编辑器选型继续保留。

## DOC 与 DOCX

DOC 采用 OLE 容器和 Word 二进制结构，DOCX 采用 OOXML ZIP 包。共同输出文本不意味着能够共用保存策略。
DOC 初期定位导入，优先另存 DOCX，原件保留。RTF/HTML 伪装 DOC 须独立识别与适配。
DOCX 编辑需明确对样式、关系文件、媒体与未知 XML 部件的保留策略，不能简单用纯文本或 HTML 重建任意原件。

## PDF

预览、文字提取、注释、页面操作和正文重排是不同能力。
第一版优先页面预览、搜索与办公文档导出 PDF；扫描件 OCR 和任意 PDF 正文编辑后置。
后续评估 PDFium 或 PDF.js 页面渲染，比较依赖体积、字体、打印、分发方式与实际视觉表现。
中文 CID 字体、缺少 ToUnicode、多栏、旋转文本、表单、密码和签名需要独立样本。

## 验证方法

自动化测试使用独立构造的小样本：中文 DOCX、简单表格、XML 转义、英文 PDF、损坏容器、伪扩展名、缺失文件与大小限制；同时校验读取前后源文件字节一致。
合成样本不代表 Word/WPS 全面兼容通过。另有 3 份真实样本的文本和有限编辑验证，尚无排版质量结论。

真实语料目标：每格式先 10 份，逐步扩大至 20–30 份；记录来源及可再分发状态、预期文本、表格和图片数量、已知不支持项。
同一文件分别在 Word/WPS 或参考工具中检查；PDF 按页面渲染比对，DOCX 按编辑往返和最终分页比对。
性能记录 release 构建、文件大小、冷/热启动、耗时、峰值进程内存，避免使用 debug 耗时作为产品结论。

## DOCX 保存策略的实际发现

检查依赖源码发现 `EditablePackage::write_to` 会重新序列化 `.rels` 与 `[Content_Types].xml`。应用层因此只合入实际修改的 XML 文本部件，保留原包的关系、内容类型、媒体及未知条目载荷。
修改前后进行 ZIP 部件集合与内容验证，并重新打开最终输出包。整包 ZIP 元数据与压缩会重新生成，不能据此宣称文件字节无损或视觉排版无变化。
上游匹配器会忽略 `w:tab`、`w:br`、字段和对象边界拼接 `w:t`；应用层增加边界检查，发现查找串跨越这些边界时拒绝输出。测试覆盖制表符、换行、字段和绘图标记。
目前只提供显式的全范围文本替换；单行替换，不处理自由段落增删、修订编辑或任意格式转换。

## 基础文字编辑与 DOCX 往返

已引入 Tiptap/ProseMirror 编辑器，用于新建文档以及本应用生成且模型一致的 DOCX。支持段落、标题 1–3、加粗/斜体/下划线、无序和编号列表、简单矩形表格、PNG/JPEG 插图、撤销重做。已有外部 DOCX 仍保留原包，不能以提取正文冒充其完整可编辑模型。

Rust `document` 模块接收严格校验的树状 JSON，拒绝不支持节点/属性、非法 XML 字符、合并单元格、指定列宽、自定义图片尺寸和远程图片 URL。DOCX 生成包括正文、样式、编号定义、图片载荷与关系文件，写出前重新解析，输出禁止覆盖已有文件。
本应用生成 DOCX 内嵌版本化编辑模型和所有其他部件的 SHA-256；加载时既校验原包部件，又重新编码模型并比对正文等载荷，防止正文被外部修改或者仅模型被修改后仍使用旧模型。校验不通过保留原包并回退到正文阅读，尚不能替代通用 DOCX 导入器。

新增本地单槽草稿：编辑后 700 ms 防抖，串行写入避免旧写入覆盖新写入；Rust 采用同目录临时文件、同步和原子替换，版本校验后恢复。切换文档前提示未导出修改，导出期间继续编辑的变化保持未导出状态。原生窗口退出已联动最后一次草稿写入，见下节；真实崩溃恢复、并发窗口与真实磁盘失败场景还需进一步验证。

当前验证：13 项 Rust 集成测试通过；新增覆盖样式/标题/嵌套列表/表格/中文导出重开、图片载荷与关系、非法模型与禁止覆盖、磁盘草稿写入恢复、正文或仅模型被篡改后的拒绝。7 项界面测试通过，覆盖新建中文内容、撤销重做、表格、草稿恢复、调用真实 Rust 导出，以及可编辑模型打开。界面中文测试为浏览器文本插入，不是硬件输入法验收。编辑器截图已目视检查；未据此宣称 Word/WPS 分页兼容。

编辑器参考：https://tiptap.dev/docs/editor/getting-started/install/vanilla-javascript 、https://tiptap.dev/docs/editor/extensions/functionality/table-kit 、https://tiptap.dev/docs/editor/extensions/nodes/image 。

## 退出和切换时的草稿保护

桌面窗口通过 Tauri `onCloseRequested` 拦截关闭，显式获得 main 窗口的 `core:window:allow-destroy` 能力。未导出修改经用户确认后取消防抖计时、等待已有写入并写入最终模型，再销毁窗口；磁盘/校验失败取消关闭，保留可编辑内容。用户取消则不销毁；导出或文件操作进行中不允许退出。文件打开期间暂停原文编辑，避免文件对话框返回前产生的新修改被直接丢弃。

切换文档使用同一最终写入保护，保存失败不创建替代文档。写入队列区分“后台自动保存失败后可继续重试”与“离开前最后写入必须成功”，不能吞掉最后一次错误后仍离开。

实现中发现 Tiptap `setEditable` 默认触发更新事件，会把暂停/恢复编辑误判为正文修改，甚至把空白新文档保存进草稿槽。已对编辑锁使用 `emitUpdate=false`，现有恢复与重开测试覆盖这个回归。

新增 6 项生命周期界面测试：旧写入延迟时最终文字在销毁前写入、磁盘写入失败后保留窗口和继续编辑、取消退出、失败阻止新建文档、导出期间阻止关闭、文件操作暂停编辑且取消后保留原文。使用真实 Tauri JS window/event 包装层和模拟原生传输；不代表 Windows 原生事件、权限和 WebView2 的端到端验收已完成。

参考：https://v2.tauri.app/reference/javascript/api/namespacewindow/ 。

## 外部 Word 文档的编辑副本

DOCX 经包级预检后，通过 office_oxide IR 映射到应用自己的 Node 模型；支持基本段落/标题/样式/列表/表格/PNG-JPEG。未支持内容可拒绝，字体/版式规范化列在报告中。桌面先准备模型，再显示中文风险列表；取消或失败保留原阅读视图，接受后编辑副本进入草稿及另存流程。

DOC 使用受限大小的内存快照及显式 Doc 格式解析，检查 text_complete、解析警告、宏和附属故事，再复用 IR 转换。IR 元数据的转换警告也会阻止导入。发现 SampleDoc.doc 的分页处空段落被上游转换省略；对于段落/标题序列，在文字序列完全匹配时补回提取文本里的空段落，保留已有样式节点。其他空白变化显式提示，仍未证明任意 DOC 保真。

验证：18 项 Rust 集成测试通过；16 项界面模拟 IPC 测试通过；根与桌面 Clippy 通过。固定 SHA-256 的 simple.doc 和 SampleDoc.doc 均完成导入模型、真实 Rust DOCX 导出、重开正文精确比对（仅忽略文件尾换行）及源文件哈希检查。未做原生文件对话框/WebView2、Word/WPS 页面渲染或中文输入法实机验收。

## PDF 提取与预览解耦

Rust `inspect_for_preview` 仅允许 PDF 的文字提取错误作为 `text_error` 返回；文件读取、大小与签名检查仍失败即拒绝。CLI `inspect` 保持严格。预览候选不代表 PDF 有效，PDF.js 单独决定页面是否可打开；渲染失败保留当前文件及正文回退。桌面打开和 Word 导入现已隔离到独立进程；硬内存/CPU 配额、文件系统沙箱和其他重型操作隔离仍待完善。

PDF.js `onPassword` 接本机密码对话框，错误密码重试、取消销毁加载任务、重试重新读取。Enter 提交密码，输入框在提交/取消后清空；密码只传入本地 worker，不进入 Rust IPC 或草稿。解锁不重新运行 Rust 文字提取，现由已解锁的 PDF.js 在本机逐页提取正文，支持跨页搜索；原始 Rust 提取结果仍保持独立。

自生成 `tests/fixtures/encrypted.pdf`（AES-256、空白页、测试密码）的 Rust 检查证明提取失败可返回预览候选；实际 PDF.js 测试证明正确密码后生成 300 像素画布，错误密码可重试、取消可再打开、无效 PDF 有回退。此证据不覆盖复杂加密文件的视觉保真。

## 解锁后的 PDF 正文提取

页面打开后，如果 Rust 提取失败或为空，使用已解锁的本机 PDF.js 逐页 getTextContent。正文作为文本节点显示，可跨页搜索；不把提取内容或密码发往网络、Rust IPC 或草稿。支持手动重新提取、当前页工作完成后的停止、部分页失败继续保留其他页结果。单次最多遍历 1000 页、保留 2 Mi 字符；截断即使发生在最后一页也不能标记为完整。空白结果提示可能是扫描件或空白页，仍未实现 OCR。

项目自生成双页 AES-256 文本 PDF 验证解锁后正文与 2 处跨页搜索、第二页渲染；辅助测试验证失败页保留其他结果、取消后清理页面、末页文本上限与页数遍历上限。23 项界面及提取测试的完整回归通过；新增页数上限用例另行验证。正文顺序、中文字体映射、复杂 PDF 兼容性与原生 WebView2 验收仍需扩展。

## 编辑文档打印原型

编辑工具栏新增“打印 / 保存 PDF”和 Ctrl P。打印前复制当前编辑 DOM 到独立快照，去掉编辑和选择标记、验证图片为嵌入 PNG/JPEG，等待字体及图片解码后调用 window.print；损坏图片阻止打印并保留编辑内容。准备期间防止保存/切换并发。打印结束或关闭编辑模式清除快照，打印不会把未导出状态标成已保存。

打印 CSS 使用 A4、20 mm 页边距，隐藏整个工作区，仅输出正文；标题避免与后文分离、段落控制孤行、表格行尽量不跨页、图片限制在可打印区域。浏览器排版不等同于 Word 原始版式保真，超高表格行及复杂文档仍需扩展验证。

Playwright 截获系统 print 调用验证快照不受后续编辑影响，再使用真实 Chromium PDF 输出。pypdf 验证多页 A4、中文首尾内容和排除 UI/后续修改；Poppler 将四页输出渲染为 PNG，逐页查看中文、列表、表格及末页，无裁切/重叠。另有损坏嵌入图片阻止打印及继续编辑测试。系统打印目标选择、原生 WebView2 打印行为和专用 PDF 直接保存尚未验收，因此界面仅报告“已准备”，不宣称文件已保存。

## Windows 专用 PDF 直接导出

已实现 WebView2 ICoreWebView2_7::PrintToPdf 的 Rust/Tauri 适配，界面提供“另存 PDF”。原生保存对话框只选择新文件名；后台临时生成，60 秒等待回调，检查 64 MiB 上限/文件包络并用 lopdf 重开及检查页面，再在目标目录创建临时文件、sync_all、persist_noclobber 发布。异步回调持有临时目录，超时后也不提前删除仍可能被 WebView2 使用的目录。失败/取消保留编辑内容，PDF 导出不等同于保存 DOCX。

官方接口说明：https://learn.microsoft.com/en-us/microsoft-edge/webview2/how-to/print 。页面尺寸与边距 API 使用英寸，设置为 A4 / 20 mm；打印背景，关闭浏览器页眉页脚。

真实 Windows WebView2 测试通过：测试 feature 构建后以随机空闲 CDP 端口启动本机程序，隐藏窗口，草稿和输出隔离到独立目录。编辑中文/英文及表格，通过真实 Tauri IPC/COM 导出 PDF，再尝试同名输出，验证文件逐字节未改变。输出约 594.96 × 841.92 pt，A4 容差内。pypdf 提取包含全部测试文字；原始结果显示宋体将部分汉字映射为 Unicode 兼容部首，英文也有额外提取空格，因此只在明确的 NFKC/空白规范化后比较，并保留原始证据。Poppler 渲染检查显示中文、英文和表格正常，没有裁切/重叠。字体 ToUnicode 映射和复杂文档保真仍需改进。

29 项界面回归、2 项桌面 PDF 发布测试及桌面全 feature Clippy 均通过。原生测试旁路仅由 native-smoke feature + 显式环境变量启用，测试后已重新构建普通可执行文件。此测试未验收系统文件保存对话框交互、打印机或复杂 Word 页面保真，也未覆盖 Excel/PPT。

## 文档解析进程边界

桌面同一可执行文件在 --document-worker 模式下仅读取 stdin JSON 请求，不初始化窗口或 WebView2。支持打开 DOC/DOCX/PDF、读取本应用模型和 DOC/DOCX 导入；只读源文件。parent 通过受控 Command 参数启动自身，路径经 JSON 输入，Windows CREATE_NO_WINDOW 隐藏子进程。返回 tagged JSON，stderr 不进入界面报告。

parent 用临时文件捕获 stdout，轮询退出/响应大小/30 秒截止，超限或失败 kill + wait 回收；输入独立写线程，保证子进程不读 stdin 时仍能触发截止。读取结果限制 32 MiB，请求限制 64 KiB。该阶段先隔离异常及超时，随后补充下述 Windows 内存配额；CPU 配额和文件系统沙箱仍未实现。写入/导出部分路径尚未移入独立进程。

验证完成：16 项相关 Word 查找/替换、编辑和退出测试全部通过（40.5 秒）。此前有一次测试 worker 异常退出，未将未执行项计为通过；确认进程结束后完整重跑上述集合。原生 WebView2 运行 `tmp/native-pdf/run-sTsvMt/` 验证替换的删除线、中文和 Emoji、真实磁盘草稿、相邻输入与逐步撤销；从磁盘草稿调用 Rust 创建 `replacement.docx`，独立 python-docx 验证首段文字/删除线及表格保留。随后实际 A4 PDF、拒绝覆盖和损坏输入保护继续通过。该原生 DOCX 验证直接调用 CLI，未覆盖系统另存对话框。

正文查找新增替换输入和“替换当前匹配”。必须先用上一处/下一处定位；文字编辑或撤销刷新匹配后需重新定位。每次执行前重新校验记录范围的当前文字仍等于查询。只替换该范围，保留前后字符样式和段落结构；替换文字继承匹配首字符的全部标记（包含链接），按钮提示明确说明此规则。空替换删除匹配，相同文字不创建修改。

替换限 4096 UTF-16 单元，拒绝控制字符、换行和不完整代理对。单次 ProseMirror 事务修改正文，前后关闭历史分组，光标停在替换末尾；后续输入不会再次覆盖替换结果。沿用编辑器已有草稿队列；离开/原生操作/打印锁定时禁用。关闭文档清除替换输入。全部替换现已加入（见后续记录），正则、跨段落匹配或逐字符格式对应仍未支持。

## 全部替换与保存预算

原生验证：`tmp/native-pdf/run-1pvUV9/`。真实 WebView2 在正文删除线范围及表格里一次替换两处“原生”为“批量😀”，验证实际磁盘草稿含两处结果，再调用 Rust CLI 创建 `all-replacement.docx` 并以 python-docx 独立读取正文文字/删除线及表格文字；一次撤销恢复全部匹配，第二次撤销仅回退前一笔表格输入。之后 A4 PDF、拒绝覆盖和损坏输入打开保护全部通过。

点击全部替换时重新完整扫描当前文档，只处理原有的不重叠匹配；替换文字包含查询本身时不再次递归替换。达到 1000 命中、100000 扫描节点或 2 Mi UTF-16 文本扫描预算时，明确保守报告扫描不完整并阻止整批操作（恰好 1000 命中也按不完整处理）。段落、标题和表格均可参与，硬换行/图片边界仍不跨越。

共享 `ui/word-replace.ts` 构造倒序事务，逐项检查原范围文字、顺序、不重叠及同一文本块。修改前检查候选的 2 MiB UTF-8 正文、10000 节点/深度 32 和含图片属性的 32 MiB 草稿序列化预算；任一失败不提交。原文略超保存预算时仍允许缩减到合法大小，原文统计另设 100000 节点上限。该检查保护替换操作，不宣称覆盖其他编辑入口或全部 Rust 语义校验。

每个匹配继承首字符格式和链接，周围内容保持；空替换删除、相同替换无修改。整批共用一次历史记录和一次编辑更新，光标停在第一处结果末尾。已有当前匹配替换也复用预算检查。

19 项 Word 查找/替换、编辑和退出相关测试通过（49.5 秒）；补充大图片属性草稿预算与超节点文档缩减用例后，4 项预算/批量用例复测通过（17.4 秒）。覆盖 UTF-8 中文增长、无效输入、过期/重叠范围、原文不变、完整/不完整扫描、重复查询文字、一次撤销、格式与表格，以及真实 Rust DOCX 输出和 python-docx 独立读取。图片预算用例为合成属性，只验证序列化预算，不验证图片解码。

## DOC 正文手动分页的解析层修复

现固定一份 office_oxide 0.1.13 源码及局部补丁，来源、原始哈希和差异见 `vendor/README.md`。结构化文本清洗保留正文手动分页控制字符，PlcfSed 的非末节边界用于识别分节结束，最终 CP 哨兵不参与切节。分页拆分沿用原 UTF-8 字节坐标，因此两侧字符样式和跨分页链接的范围不会随拆分错位；UTF-16 CP 中的 emoji 也有测试。纯文本预览保持换行约定。

正文手动分页生成应用 pageBreak；表格/列表内部尚不能保留的分页给出解析警告并阻止编辑转换。原有无结构回退路径仍显示分页丢失风险。节元数据缺失或非法、以及结构化段落没有覆盖正文尾部的情况明确警告并拒绝；不会把 piece table 的完整性误当成结构化转换完整性。

真实空/空白普通段落从 DocParagraph 直接保留，根导入层仅对无结构回退执行原有空行补偿；空节结束符不制造空段。自制 binary DOC 回归输入可从 `scripts/make-doc-pagination-fixtures.py` 重现：完整样本保留正文/空段/分页/正文并转存 DOCX 重读，不完整 PAPX 样本拒绝转换。样本不代表 Word 或 LibreOffice 的兼容认证。

最终 vendor 1,235 项、Rust 核心 111 项通过。全量 UI 179 项通过后，末尾完整性和空段补充又经 9 项导入/打印回归验证。固定真实 SampleDoc 配对输出经独立 python-docx 核对段落数组及 1 个显式分页一致；实际原生 WebView2 导出 PDF 两页，逐页文字与 A4 页面尺寸经 pypdf 检查。原生成功目录为 `tmp/native-doc-pages/run-2iEb9t/` 和 `run-Ot54zS/`，详细命令及边界见 REGRESSION.md。分节布局、自动分页、复杂样式和更多真实语料仍是未完成项。

## 历史：Word 半点字号与 DOCX 样式字号继承

编辑模型新增独立 `fontSize` 标记，属性为整数 `halfPoints`，范围 2–3276（1–1638 pt），不接受字符串、浮点表示、重复标记或额外属性。Rust 导出同时写入 `w:sz` 和 `w:szCs`；未指定字号的旧模型保持原有输出样式。自制历史基线 `authoring-before-font-size.docx` 可经完整包验证重新编辑，原模型再次导出的全部 ZIP 部件逐字节一致，不能通过重建该样本掩盖兼容问题。

导入将可解析的有效字号保留到文字节点；同字号的字体/脚本分段仍合并，4,000 段混排回归没有因标记增加而越过结构预算。DOCX 默认段落样式按 `w:default` 选择，不依赖 Normal 名称；省略 pStyle 和明确未知 pStyle 的缓存分开。标题的字号保留真实段落样式链、字符样式及直接设置的有效值，含复杂文字 `szCs` 和强制复杂文字属性，其他标题样式仍沿用既有规范化。字体名称、颜色、默认字符/表格样式及完整样式兼容未在本轮实现。

解析层不再把带单位的字号去单位并四舍五入：13.5pt 精确转为 27 半点，in/cm/mm/pc/pi 也用检查溢出的整数有理数换算；非整数半点、非法后缀和溢出明确拒绝。缩进、行距等其他度量解析没有借此扩大支持声明。vendor 的三个 DOCX 文件单独保存可逆补丁，原 DOC 分页四文件补丁保持独立，七个之外的上游文件与原始 128 文件哈希清单一致。

界面支持混合选区、局部文字、光标后续输入、Enter/应用按钮、默认字号及清除格式。全选后立即更改 DOM 局部选区会先同步新选区；输入转焦到应用按钮时保留尚未提交值。字号包在上下标之外，代码文字允许与字号共存。操作只给文字添加标记，粘贴 HTML 时清除硬换行上的字号；有效 pt/px 只接受精确半点转换。字号事务在提交前检查节点、深度、正文和草稿字节预算，失败不产生正文修改、历史或草稿；该检查不代表所有其他编辑入口均已覆盖。

该阶段的实际验证结果记录在 REGRESSION.md。当时缺省编辑/打印字号与 DOCX 缺省样式尚未统一，后续已通过文末 `standard-v2` 实现新文档默认值一致；“默认”仍表示移除显式标记并继承所属 profile 和段落样式，旧文档不自动升级。PDF 物理字号、字体替代、复杂文字形状和完整 Word 版式是不同验证维度。

## 历史：Word RGB 颜色与主题色导入

新增 `textColor` 标记，唯一属性 `rgb` 为六位大写 ASCII 十六进制；拒绝重复标记、额外属性、非法值及非文字节点。导出显式颜色优先于链接默认蓝色，每个 run 仅写一个 `w:color`；未指定颜色的旧模型输出不变，旧自有包逐部件字节校验继续保留。导入把可解析的 RGB 规范化为标记，只有全部标记相同的相邻文字才合并。

工具栏有色盘、HEX 输入、一键黑色和恢复默认，支持部分/混合选区、光标后续输入、撤销及草稿。黑色色块避免原生色盘确认初始黑色时不触发 change；取消色盘不提交修改。共享文字标记事务保留原字号边界及修改前预算检查，粘贴清除非文字节点上的标记，代码/链接/上下标/表格可以共存。链接字形颜色已保留，浏览器外层链接的下划线仍可能采用默认色，这是与 DOCX 装饰外观的已知差异。

解析库单独提供 Word 主题色解析，保留其他格式既有算法。按 [MS-OI29500 §2.1.72](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/8229a077-7fc8-4fba-96cc-c77b6a4fc768) 使用 HSL 亮度变换，tint 优先于 shade；缺主题时 `w:val` 已是最终备用 RGB，不重复施加变换。标题采用真实默认/段落/字符/直接颜色链，auto 覆盖仍降为无显式色。WML 的 dark1/text1/background1/hyperlink 等名称与 DrawingML 名称分开解析，非法属性拒绝，六字节 Unicode 色值不会因切片而 panic。

主题色固定为 RGB 后不再动态联动，自动色或无备用的无法解析主题色使用编辑器默认值。HSL 采用完整精度后四舍五入到 8 位 RGB；`4F81BD/99` 得 `95B3D7`，`C0504D/BF` 得 `953735`，后者与微软示例 `943634` 每通道差 1，未证明与 Word 内部量化逐位一致，因此提示近似转换。集成测试固定了独立 Python colorsys 计算结果，并分别验证有/无主题、标题及静态重导出。

自定义 `clrSchemeMapping` 暂时拒绝编辑导入，标准缺省或显式默认映射放行。当文字引用的主题色方案含尚不支持的 DrawingML 变换或其他颜色来源时也拒绝，避免把原始基色误当最终色；位于 fmtScheme 的形状外观变换不据此误拦截。此审计仍不是完整 OOXML 兼容证明。普通主题解析只支持 sRGB 和带 lastClr 的系统色；完整主题和字体族编辑仍待扩展。该阶段提出的默认值一致性问题在后续 `standard-v2` 中处理，实际排版一致性仍需验收。

RGB 颜色阶段结束时的只读审计发现：编辑与打印正文 12 pt，DOCX 11 pt；标题分别为 19.5/16.5/13.5 pt 与 18/15/13 pt。编辑默认色 `#253343`、打印 `#111`，DOCX 未显式声明；字体族、行高和边距也不同。当时的结论是先定义版本化样式配置，冻结旧 V1 编码字节，再让新配置随文档、草稿、IPC 及打印克隆流转；直接改原 writer 的 styles 会使正常旧包无法通过模型一致性重开。此审计提出的新文档默认值问题已由下节 V2 实现解决，旧 V1 保留原样；字体实际回退和自动分页仍需独立验收。

此次一致性审查额外复现了自有 DOCX 缺失部件校验漏洞：仅删除样式、仅删除图片或两者同时删除，并同步删内嵌哈希记录，旧加载器都会误接受。现重编码后先比较完整部件键集合，再逐个比较内容；三种负例均拒绝，旧版字节编码保持不变。最终核心 128 项、补丁后文字 UI 18 项及原生字号/颜色/DOC 分页检查通过；此前本轮跨格式 191 项全量结果和执行边界见 REGRESSION.md。

## Word standard-v2 版本化默认样式

`standard-v2` 已实现新建文档、外部 DOC/DOCX 编辑副本、DOCX 导出及打印快照的统一默认值。外部导入保留可表达的显式字号和 RGB，同时在报告中提示默认文档样式规范化；不会修改原件。旧自有 DOCX 直接重开和旧草稿恢复继续使用其原有 V1，不根据应用当前默认值自动迁移。

| 默认项 | standard-v2 |
| --- | --- |
| 字体 | ASCII、高位拉丁及复杂文字使用 Arial，东亚文字使用 Microsoft YaHei（微软雅黑） |
| 正文 | 11 pt、黑色 `000000`、常规字重、1.5 倍行距、段前 0/段后 6 pt |
| 标题 1 / 2 / 3 | 18 / 15 / 13 pt、粗体、黑色、1.5 倍行距、段前 12/段后 6 pt；与下段保持 |
| 页面 | A4，四边页边距 25.4 mm |

根节点 `doc.attrs.styleProfile` 只允许省略或字符串 `standard-v2`：省略是 V1，显式 `legacy-v1`、`null`、未知值及非根节点上的该属性均拒绝。现有 Node IPC 接口保持不变。样式定义一经发布即固定，未来若改变默认值，需要另起 profile，保证旧自有包仍能通过重编码一致性校验。

磁盘草稿沿用同一个 `draft-v1.json` 文件名；内部 `version` 根据 profile 分别为 1 或 2，加载时严格核对，两者不能混搭。DOCX 分别使用 `rust-wps/model-v1.json` 和 `rust-wps/model-v2.json`，包 authoring 关系指向所属版本。加载器拒绝双模型、未知 `model-v*.json`、文件名/内嵌版本/profile 错配，并检查全部非模型部件的哈希覆盖、完整部件集合及重编码内容；同步伪造哈希不能掩盖缺少样式或图片部件。

Rust writer 共用正文编码流程，按 profile 选择默认样式、模型版本和包关系。V1 原 XML 与历史样本各 ZIP 部件字节不变。V2 同时声明 `sz/szCs`、默认 `b/bCs=false`、标题 `b/bCs=true`；显式粗体和斜体分别写 `b+bCs`、`i+iCs`，避免复杂文字仍继承普通字重。表头没有隐式粗体，编辑器 V2 表头默认字重与导出保持一致；显式字号和颜色继续优先。

前端将 profile 注册为 ProseMirror 根属性，保存快照会去掉仅供旧模型内部使用的 `null`，保留 V2 属性；恢复新模型先校验 profile，再关闭当前文档。自动草稿、离开最后写入及另存使用同一快照入口。打印克隆保留 profile 标识；V2 的命名 A4 打印页面和原生 PDF 请求使用 25.4 mm 边距，旧 V1 打印设置继续保留原值。

Rust 核心 136 项、桌面后端 10 项通过；其中 8 项 profile 专项覆盖 V1 历史部件字节、草稿槽版本切换、V2 固定样式与完整模型重开、复杂文字显式粗斜体、非法属性不写入、版本错配及包部件篡改。界面全量 194 项通过、2 项旧默认颜色期望失败；独立核对后仅更新测试预期并补充默认色读取断言，相关 10 项复测通过。最终原生 V2 草稿、DOCX/worker 重开和 PDF 默认字体/字号/黑色/边距探针通过，已恢复普通桌面构建。完整计数、证据和执行边界见 [REGRESSION.md](REGRESSION.md)。

这一轮统一的是默认样式声明和版本传递。实际字体是否可用、字形回退、复杂文字塑形、自动分页、表格细节和外部复杂版式仍可能不同；尚未提供字体族编辑、完整主题或 Word/WPS 页面级保真。系统打印窗口的纸张、缩放和页眉页脚设置也可能影响最终结果。
