# Excel 探索与实现顺序

文字/PDF 原型已经可运行并完成部分桌面回归；复杂排版仍继续完善。现在进入后续 Excel 技术探索，先 XLSX，再 XLS，最后扩展与 PPT 的统一工作区。Excel 阶段尚未完成。

当前 `cargo run --locked -- inspect-xlsx <file.xlsx>` 提供只读 JSON 清单。复用固定版本 office_oxide 0.1.13 的原始 XLSX worksheet/cell API，避免转换为稠密文档表格：最远单元格 XFD1048576 不会令输出展开为十亿格。

清单保留工作表顺序、名称、可见性、种类、声明范围、合并范围、实际单元格地址、从零开始的行列、类型化值、公式文字和数字格式。日期数字保留 Excel 序列值与 number_format，并单独记录 1900/1904 系统；尚未完成统一日期显示。公式保留源缓存，不执行、刷新或访问外部链接。formula_cache 为 present、absent 或 empty_or_absent；上游将部分空 v 元素解析为空字符串，最后一种必须视为歧义，不能声称已经计算。

输入快照上限 64 MiB，复用 ZIP 4096 项/128 MiB 展开量/CRC/重复条目预检；报告限 100 个工作表、100,000 个实际单元格及 4 MiB 文字/公式。拒绝不可读工作表、重复地址、非有限数值。桌面打开 XLSX 已接入独立 worker，沿用 30 秒超时及 Windows Job 内存限制。

桌面支持只读工作表切换（包括明确标注的隐藏表）、单元格选中、方向键移动、地址跳转和源公式栏。网格只渲染可视区域，最多 1,800 个单元格节点；可跳至 XFD1048576。默认显示原值或源缓存，可切换有限数字格式显示；合并效果尚未渲染。打开失败保留当前文档；切换到文字编辑会释放网格。

`tests/ui/spreadsheet.spec.mjs` 使用真实 Rust CLI 解析的 openpyxl 输入，验证网格、最远地址、公式缓存提示、状态保留与文本注入；界面测试模拟 IPC。`scripts/check-workbook-worker.mjs` 单独验证真实桌面可执行文件的 worker 协议与 CLI 报告一致；`scripts/native-workbook-smoke.mjs` 验证真实窗口的编辑、草稿、计算、导出及关闭保护。

验证包括独立手写 OOXML 和 openpyxl 生成工作簿：中文共享/内联文本、数值、布尔、错误、公式缓存值/缺失、1904 日期序列和格式、隐藏表、合并范围与最远单元格；源文件字节保持不变。`scripts/check-spreadsheet.py` 使用 openpyxl 创建独立输入并调用真实 Rust CLI。它没有证明 Excel 应用页面保真，也没有验证共享/数组/动态公式及复杂对象。

已建立独立可编辑稀疏模型 `spreadsheet_edit::Workbook`（version=1），已由 JSON/CLI 和桌面编辑界面共用。模型使用从零开始的行列，支持空、文本、有限数值、布尔、公式文字及数字格式，工作表名称和隐藏状态。新建默认使用 1900 日期系统，编辑模型可保留 1904 标记；日期使用原始序列值和格式；不接受只读报告作为完整编辑模型。

运行 `cargo run --locked -- create-xlsx docs/examples/workbook-v1.json new.xlsx` 创建新文件。公式文字不含前导等号，导出不写虚构缓存；有限计算结果独立于导出模型。文件在同目录临时写入，经 ZIP 预检和实际重读逐格核对名称、隐藏状态、类型化值、公式/缓存与数字格式后，原子发布且不覆盖目标。固定版本上游缺少 Normal 命名样式，生成包时补齐；openpyxl 校验将此类警告视为失败。

`tests/spreadsheet_edit.rs` 验证稀疏最远地址、公式缺失缓存、类型/格式、输入边界和拒绝覆盖。`scripts/check-workbook-export.py` 使用真实 CLI 导出，再由独立 openpyxl 读取，验证上述内容及源 JSON 字节不变。它没有验证 Excel/WPS 原生渲染与重算行为。

导出包现包含 `rust-wps/workbook-v1.json`，并在 Content Types 注册 JSON 部件。`load_authored_xlsx` 校验模型版本和边界，重新编码完整工作簿，逐项比较所有未压缩 OPC 部件（模型本身除外），同时要求部件集合一致。仅 ZIP 压缩/时间戳变化可以通过；正文、公式、样式、关系、模型单独修改以及增删部件均不能授予直接编辑能力。这个保守边界只适用于本应用生成且内容仍一致的文件，外部工具重保存通常需要另走编辑导入审计。

`cargo run --locked -- read-xlsx-model authored.xlsx` 输出经验证的编辑模型 JSON；缺失模型或内容不一致时返回错误。可修改 JSON 后用 create-xlsx 另存新文件。独立导出回归执行完整的创建→模型重读→修改数值→另存→openpyxl 核对，确认原工作簿不变、公式仍存在、缓存保持缺失。桌面现已接入类型化输入、撤销重做和独立工作簿草稿。

桌面 worker 从同一份最多 64 MiB 的源快照生成只读报告及校验编辑模型，避免两次打开路径得到不一致内容。有效模型通过 `workbook_model` 返回；不存在模型时继续只读；模型失效但工作簿可读时附带警告并保留只读预览。桌面在模型有效时启用编辑，外部工作簿默认只读，可通过单独导入审计建立编辑副本。真实 worker 回归验证有效模型、模型单独修改、公式修改与无模型输入，均检查源文件不被改写。

工作簿草稿核心现提供 `save_draft/load_draft`：使用独立 `workbook-draft-v1.json` 槽位，模型校验及 16 MiB JSON 上限，同目录临时写入、同步后原子替换。缺失草稿返回空；损坏、过大和版本不支持返回错误；校验失败保留旧草稿。桌面后端已注册 `save_workbook_draft/load_workbook_draft/save_new_workbook` 命令，另存使用系统对话框并调用发布前校验的 XLSX 导出。界面已接入新建工作簿、恢复工作簿草稿和另存 XLSX；修改后约 700 ms 串行保存草稿。离开或关闭时立即写入最后状态，写入失败保留工作簿并阻止离开。当前只有一个工作簿草稿槽，不是版本历史。浏览器 IPC 模拟和真实 WebView2 回归均覆盖工作簿退出保护；系统文件对话框的交互仍待单独验收。

桌面编辑使用 `WorkbookEditor` 共用状态模型，单元格撤销按差异保存，工作表操作保留前后稀疏快照；最多 100 个事务，历史 JSON 的 UTF-8 大小估算上限 32 MiB。导出按版本标记，撤销到已导出版本会恢复无未导出修改状态。类型显式选择：文本保留 001，数值接受十进制/科学计数法但拒绝空串、NaN/Infinity 和十六进制；布尔输入 true/false；公式可输入前导等号，模型中去掉一个等号。点击“计算公式”显示有限计算结果，修改后立即失效，导出不虚构缓存。清空已有样式的单元格保留数字格式。输入需通过应用按钮或 Enter/Tab 提交，未提交文字不属于模型修改；矩形选区通过 Shift 点击或 Shift 方向键扩展。

界面回归覆盖外部工作簿只读、编辑/撤销/草稿/导出、新建和恢复、失败保留及退出保护；模拟 IPC 的导出与读取仍使用真实 Rust CLI。完整 81 项界面回归通过，含 XLS 只读预览、外部 XLSX 审计导入、矩形排序、数字格式、公式计算/失效、工作表管理及 Word/PDF 原有用例。真实 WebView2/Tauri 回归另验证计算 worker、结果格式、修改失效、未缓存导出、草稿、拒绝覆盖和关闭保护；系统文件对话框交互未覆盖。每次应用修改目前会重建工作簿展示快照，大表编辑性能需要进一步优化和测量。

原生工作簿回归：`npx tauri build --no-bundle --debug --features native-smoke` 后运行 `node scripts/native-workbook-smoke.mjs`，最后恢复 `npx tauri build --no-bundle --debug`。测试启动真实隐藏 WebView2，以随机本地 CDP 端口操作 UI，执行实际 IPC、独立 worker、草稿落盘/恢复、XLSX 导出及模型重读，逐项比较完整模型并检查源文件字节不变。保存目标已存在时拒绝覆盖；把隔离草稿目标临时替换为空目录制造写入失败，确认真实窗口保持打开、内容保留，解除故障后再次关闭并核对最后修改落盘。每次运行在 tmp/native-workbook/run-* 保存 report.json。测试 feature 通过环境指定打开/保存路径并隔离草稿，未覆盖 Windows 文件对话框；普通构建忽略这些路径变量。

修复了恢复草稿前的覆盖问题：未修改的已打开文件离开时只等待已有队列，不主动覆盖工作簿草稿；有修改、待写定时器或先前写入失败才提交当前状态。回归覆盖编辑→保存→重新打开原文件（原值）→恢复先前草稿（修改值）。

矩形内容操作已接入：Shift 点击或 Shift 方向键扩选；网格获得焦点后 Ctrl+C/Ctrl+V 复制粘贴，Delete/Backspace 整块清空，Ctrl+Z/Ctrl+Y 撤销重做，Ctrl+S 另存。外部 text/plain 按 TSV 解析，支持引号内制表符、多行文字、双引号转义和末尾换行；外部内容统一按文本粘贴，保留 001 和公式字面值。本应用可编辑网格复制附加 version=2 类型矩阵和复制起点，内部粘贴保留数值/布尔/文本/公式/空值，保留目标单元格既有数字格式，不复制源样式；只读工作簿复制为文字。version=2 内部公式复制调整 A1 相对引用，version=1 旧载荷缺少源地址时按原文保留并提示；外部文本仍不解释为公式。当前没有剪切、鼠标拖选、整行整列操作及 HTML 表格粘贴。

批量操作先校验全部内容和地址，再提交一个事务。越界、重复地址、非法数值/文字或超出工作簿文字预算时整体拒绝，不产生局部写入和历史步骤。每次复制/粘贴/清空最多 10000 格，剪贴板文本及类型载荷各限 4 MiB；历史同时按事务数和序列化估算量约束。选区高亮只渲染可视区域。测试使用浏览器 DataTransfer/ClipboardEvent 验证事件链、内部类型、TSV 多行/前导零、整块撤销与清空、边界拒绝，以及真实 Rust 导出重开；尚未验证操作系统剪贴板及 Excel/WPS 跨应用粘贴。

公式复制现在按源矩形起点与目标左上角的行列差平移 A1 引用，遵循 [Microsoft 相对/绝对/混合引用规则](https://support.microsoft.com/en-us/excel/switch-between-relative-and-absolute-references)。`$` 固定的部分不移动；支持单元格、矩形范围、整行/整列范围、工作表和外部工作簿前缀，越界引用生成 #REF!。字符串、中文/补充平面 Unicode、函数名、科学计数法、工作表名及结构化引用括号块保留原文；结构化引用中的单引号转义按 [Microsoft 结构化引用语法](https://support.microsoft.com/en-us/excel/using-structured-references-with-excel-tables) 处理。内部剪贴板 v2 原点和范围需通过边界校验；引号/方括号未闭合或平移后模型校验失败时整块粘贴拒绝。

这是词法层 A1 平移，不是公式语法验证、计算引擎、命名范围解析、R1C1 平移、插入行列时的引用维护或跨工作簿链接管理。`tests/ui/formula-references.spec.mjs` 用独立 openpyxl Translator 对照有效引用样例，并检查锚定、中文/转义、函数和科学计数法、结构化引用、越界与畸形输入；UI 回归检查实际内部复制、整块失败保留、撤销重做，以及真实 Rust 导出后重读公式。未在 Excel/WPS 原生应用中验证所有语法。

只读清单不支持编辑、保存、重算、图表渲染、宏、透视表行为或完整样式重建，不能作为完整 Excel 兼容证明。

自建及通过模型审计的工作簿现支持新增、重命名、删除工作表，与单元格编辑共享撤销/重做和草稿保存。名称检查覆盖重名、非法字符、31 个 UTF-16 单元限制；最多 100 张，必须保留至少一张可见表。工作表操作保存前后稀疏模型，单次及累计撤销历史限制为 32 MiB，超限操作整项拒绝。

数字格式工具栏支持常规、整数、小数、千分位、百分比、日期、时间、文本显示和自定义代码，可一次应用至最多 10000 个选区单元格；一次操作整体撤销，草稿和 XLSX 保留代码。恢复常规会删除仅有格式的空单元格，清空内容则保留其格式。单个代码最多 1024 个 UTF-8 字节，工作簿总文字/公式/格式预算为 4 MiB；越界、字符非法或超预算时整项拒绝。自定义代码不做完整 Excel 格式语法校验。

格式仅修改显示属性，不转换单元格内容类型或数值。日期仍输入日期序列数，文本显示 `@` 不会将数值转换为文本。预设含义参考 [Microsoft 数字格式说明](https://support.microsoft.com/en-us/excel/get-started/available-number-formats-in-excel)。`tests/ui/number-format.spec.mjs` 验证矩形选区、空白格式、撤销、预算、草稿及真实 Rust 导出，并用独立 openpyxl 检查百分比、公式和日期。

网格默认显示原值，勾选“格式显示”可预览数值单元格的精确预设代码 `0`、`0.00`、`#,##0.00`、`0%`、`0.00%`、`yyyy-mm-dd`、`hh:mm:ss`；`General`、空代码和 `@` 保留原值。小数点固定为点，分组固定为逗号，采用 Intl 数值舍入；没有完整地区格式或自定义代码解释器。不支持的代码、负日期/时间或超范围序列回退原值，以点状下划线、悬停文字和选中信息提示。公式栏始终显示原值；复制的外部纯文字随当前显示模式，内部类型化剪贴板保留原数值/公式。视图开关不写入草稿、不产生撤销记录。

日期按工作簿的 1900/1904 系统转换，采用 UTC 避免时区偏移；保留 1900 系统序列 60 对应的兼容日期 `1900-02-29`，1900 系统序列 0 明确回退原值，1904 系统序列 0 对应 `1904-01-01`。仅支持不晚于 9999-12-31 的日期，时间取小数日并舍入至秒，不支持累计时长。依据：[Microsoft 日期系统](https://support.microsoft.com/en-us/excel/date-systems-in-excel)、[1900 闰年兼容说明](https://learn.microsoft.com/en-US/office/troubleshoot/excel/wrongly-assumes-1900-is-leap-year)。`tests/ui/number-display.spec.mjs` 覆盖两套日期系统、边界、独立日期对照、原值编辑、剪贴板和不支持格式提示；未验证全部 Excel/WPS 原生显示行为。

工作表支持隐藏/恢复显示和向前/向后移动，保留至少一张可见表。隐藏表仍可从标注“隐藏”的列表项进入，以便恢复显示，导出 XLSX 保存其隐藏属性。移动维护有限的三维引用：端点未交叉时保留前缀，移过另一端时向原范围内相邻表收缩；因此范围成员可能变化。字符串和外部链接保持原文，公式未重算。独立 openpyxl 检查导出顺序、可见性及更新后的公式；尚无原生 Excel/WPS 对照验证。

重命名维护当前工作簿公式中的工作表前缀；删除单表引用产生 `#REF!`，三维引用端点向剩余范围收缩，删除内部表时前缀保留。字符串、结构化引用和外部工作簿链接保持原文。这是有边界的词法维护，未覆盖完整公式语法或 Excel/WPS 原生行为验证；三维范围的删除规则参考 [Microsoft 文档](https://support.microsoft.com/en-us/excel/create-a-3-d-reference-to-the-same-cell-range-on-multiple-worksheets)。测试覆盖混合撤销、失败原子性、界面操作与真实 Rust XLSX 导出重读。







## 矩形区域排序

自建及已验证的编辑模型支持最多 10000 格的矩形排序。工具栏“选区排序列”从 1 开始，相对于选区左侧计数；可指定首行为表头。排序仅移动所选矩形内各行的内容和数字格式，不自动扩展到邻列。相同键保持原行序，真正空白位置升序和降序均放末尾；空字符串仍是文字。类型升序为数值、文字、布尔，降序反向，数值按原值比较，日期按序列数比较。文字使用固定 zh-CN Intl.Collator（区分大小写/变体，不按自然数字排序），不是全地区 Excel/WPS 排序兼容承诺。

公式作为排序键时必须有当前修订的有效计算结果，错误或未计算会拒绝整次操作；不用旧缓存或公式原文冒充排序值。公式随行移动时使用现有 A1 相对引用平移，绝对行保持不变；选区外公式原文保留，未提供 Excel 完整移动依赖维护。排序后清空当前计算结果并要求重新计算。无法平移的畸形公式或超出模型/历史预算时整项拒绝，不产生局部修改。

排序是一个稀疏历史事务，支持整体撤销/重做，使用同一草稿和 XLSX 导出路径。`tests/ui/workbook-sort.spec.mjs` 覆盖稳定性、表头、两种方向、稀疏空白、格式移动、混合类型、公式平移、失败原子性、公式键计算失效、界面选区/草稿，以及真实 Rust 导出后的独立 openpyxl 核对。原生 Excel/WPS 排序结果对照、多列排序、筛选和完整依赖维护尚待实现。功能语义参考 [Microsoft 区域与表格排序](https://support.microsoft.com/en-us/excel/sort-data-in-a-range-or-table-in-excel)。

## 外部 XLSX 的审计导入

CLI `import-xlsx <source.xlsx>` 返回 `model/risks/blockers`；有阻止项时 model=null。桌面打开外部文件仍为只读，点击表格工具栏“导入编辑副本”由同一隔离 document worker 读取一份源快照并审计，然后展示损失和阻止项。只有无阻止项且用户接受变化才建立未保存编辑副本、写入独立工作簿草稿。取消、解析失败或阻止项保留只读视图；源文件不改写，保存仍只发布新目标。

当前恢复普通工作表的稀疏数值/文字/布尔/空白、普通及后端成功展开的共享公式、数字格式和 Hidden 状态。字体/颜色/边框、富文本、行列尺寸和隐藏、视图/打印/页眉页脚、主题及文档属性不保留，全部列入固定风险提示。源公式缓存丢弃，不当作新计算结果。审计逐部件、逐 XML 元素检查允许范围，并核对源实际 cell/formula/sheet 数量与读取报告一致；未知部件/元素不授予编辑模型。不是完整 OOXML schema 校验，也不是无损导入或完整兼容性证明。

VeryHidden、非普通工作表、保护属性、定义名称、合并、筛选、图表/图片/评论、宏/签名、外部关系、数组/数据表公式、独立错误值及 ISO 日期类型等目前阻止导入。数字和布尔的非法源值拒绝，避免后端宽松转换。沿用 64 MiB 源、4096 ZIP 部件、128 MiB 展开、100 张表、100000 实际单元格及 4 MiB 文字/公式/格式限制；未知诊断最多 128 类。文档依据：[CellFormula](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.cellformula?view=openxml-3.0.1)、[Date1904](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.workbookproperties.date1904)。

`tests/spreadsheet_import.rs` 验证基础转换及重开、关键阻止项、坏包、源大小和非法数值。`scripts/check-workbook-import.py` 用独立 openpyxl 生成外部输入，实际 Rust CLI 转换、修改、导出，再由 openpyxl 核对前导零、数值、布尔、公式、数字格式、隐藏表、空白格式及缺失缓存，核对原件 SHA-256 不变。界面回归验证审计/取消/接受/草稿/失败/阻止项；`scripts/check-workbook-import-worker.mjs` 对照真实桌面 worker 与 CLI。原生 Excel/WPS 对照和更多外部语料仍待完成。

## 编辑模型的日期系统

version=1 增加可选布尔字段 `date1904`，缺省/false 表示 1900，true 表示 1904。false 序列化时省略，旧模型、旧草稿和既有自建包的默认含义不变。错误类型拒绝；不是按格式或数值猜测日期系统。导入从源 workbookPr 读取并保留，导出写入同一标记，逐包内容校验和导出后的实际读取会核对它；仅修改包中日期系统而不修改模型时拒绝编辑重开。

原始数字和公式不做 1462 天平移。前端快照、工作表操作历史、草稿、恢复、工作簿视图和数字格式显示传递同一标记；日期显示切换不改变数值。当前没有在 UI 中更换既有工作簿日期系统的控件，也不提供跨日期系统复制的日期转换。

独立 openpyxl→Rust 导入→修改→导出→openpyxl 对照两套日期系统的 2024-01-01，并验证源字节不变。Rust 测试覆盖 1904 导入、草稿、验证重开、包标记篡改和旧 JSON 默认；界面测试覆盖序列 0、修改为 1、工作表新增/撤销、草稿和真实导出。1904 日期系统不再属于导入阻止项，其他审计限制仍有效。

## 键盘连续录入

## 工作簿查找
